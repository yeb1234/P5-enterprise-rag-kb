面试讲法

生产链路是 先按权限过滤，再重排，再进模型： Milvus expr + filter_candidates 双重过滤，RRF 融合，P0 才加带降级开关的 Rerank。 本切片只有「ready 文档的分块」这一层前置条件，关键词重叠打分替身向量检索； 未启用重排、未接模型，页面字段刻意与生产口径对齐，方便对照着讲。

新鲜度策略

有效分 = 相关分 × (1 − blend + blend × 衰减)；衰减 = 0.5^(年龄/半衰期)，下限 demote_floor。适用性门控不受开关影响：未来生效与已过期文档始终按规则处置。

模型设置

切换 LLM / 向量 / 重排提供者：本地 LM Studio、外部 DeepSeek 或离线占位。保存即时生效，无需重启。

LLM 生成

V4.1 系列默认会先输出思考过程；检索问答要低延迟，默认在请求里显式关闭。该字段经实测生效：推理 token 从 55 降到 0，耗时约减半；网关元数据里的布尔 reasoning 参数实测无效。

同一 key 下多模型可切（deepseek / glm / kimi / minimax / qwen / vision），密钥在 .env 的 DISCOVERY_API_KEY。

提示：Qwen3 系列是推理模型，正文可能为空；建议选非推理的 coder 模型。

外部模型：—；密钥在 .env，不落库、不下发前端。
向量检索（Embedding）

与重排共用 .env 里的硅基流动密钥（RERANK_API_KEY 或 WEBAPP_EMBEDDING_API_KEY），不落库、不下发前端。向量按「provider:模型」隔离缓存。

重排（Rerank）
使用当前 LLM 对候选打分排序；会多一次模型调用（当前 LLM 为离线占位时自动跳过）。

密钥放 .env 的 RERANK_API_KEY，不落库、不下发前端。

说明：LM Studio 不暴露 /v1/rerank；可选「LLM 打分重排」或外部 rerank（硅基流动免费、Cohere 风格格式兼容）。

检索路由（三路取证）

同一个问题，三路各取所需：向量检索从原文里找证据，图谱检索沿关系找线索，LLM Wiki 读整理好的业务知识。开几路由你组合；多路同时命中的结果排在最前面。
