| 参数组 | 设定 | 质量四维 | `answer_economy` | 平均延迟 |
|---|---|---:|---:|---:|
| A | RGB 官方 `temp=0.2 / passage=5 / noise=0.6` | 1.000 | 1.000 | 1347 ms |
| **B** | **确定性贪心 `temp=0 / passage=5 / noise=0.6`** | **1.000** | **1.000** | **1163 ms** |
| C | `temp=0 / passage=3 / max_tokens=768` | 1.000 | 1.000 | 1356 ms |

**收敛结论**：三档质量与精简度**全部打平**，说明样本已饱和，减少注入文档（C）也无可判定收益。
采纳 **B**，主要依据不是单次延迟差（1163 vs 1347 ms 可能受网关抖动影响，未做多次观测），
而是调研结论：`temperature=0` 贪心解码是降低 run-to-run 方差的首要设置，对**评估可复现性**最关键；
同时 B 保留 RGB 官方的 `passage_num=5 / noise_rate=0.6` 上下文设定，便于与公开基准口径对齐。
C 的 `passage_num=3` 会减少噪声文档、改变被测条件，且 `max_tokens=768` 无收益 → 否决。

定稿 run：`RUN-b1a734b77e26`（12/12 命中缓存，零新增 API 调用）。

> 诚实边界：`temperature=0` 在共享 GPU 批处理下**不保证**逐字节确定（见 `datasets/SOURCES.md` §4）；
> 本工作台靠「固定 prompt/参数/模型哈希 + 原始回答落盘 + 缓存复用」保证可追溯，而非只依赖温度值。

共性结论

  • 实测 6 个模型在 max_tokens=256 的探活下均返回正文（2 字）、reasoning_only=False；因此「零正文」不是推理模型专属，本轮未复现 reasoning_only 现象
  • 实测 max_tokens=24 时 6 个模型全部返回空 content（含非推理型），属网关侧 token 预算行为；统一要求 max_tokens>=512，不把它归因于模型类型
  • 延迟差异达数量级：deepseek-v4.1-flash-1017 26.4s，deepseek-v4-pro-0813 0.8s，minimax-m3 0.8s、glm-5.3 1.7s、qwen3.8-27b 2.8s、kimi-k2.6 3.6s；超时须按模型分级
  • temperature=0 / top_p=1 在 6 个模型上均被网关接受（HTTP 200），可用于确定性参数对比
  • 可观测差异主要是延迟与思考块内联（项目既有实测），而非协议不兼容；适配层统一走 OpenAI 兼容 /chat/completions，仅按模型调整 timeout / 标签过滤 / token 预算

  • 样本为 12 条自建中文数据，依据公开基准任务定义构造，不是 RGB / SQuAD 官方数据抽样，不得称「在官方基准上的分数」。
  • 本工作台是平行于 eval/ 冻结占位体系的新体系；eval/ 的 __TBC__ / NOT_COMPARABLE / real_api 阻断口径未改动。
  • 字符串匹配评分对同义改写不鲁棒；未使用 LLM-as-judge，避免裁判漂移。
  • 离线模式 comparable=false，仅用于验证链路可跑，其分数不进入任何真实结论。
  • 未做全局并发闸/令牌桶、压测、质量基线冻结；RGB 许可为 CC BY-NC-SA 4.0，商业用途需另行授权。
