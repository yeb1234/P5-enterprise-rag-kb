# `evalfmt/` · 多格式文档评估（解析 · 检索 · 生成）

> 一句话：**把格式换掉，看整条 RAG 链路每一层各掉多少。**
> 10 份语料 × 8 种可入库格式，覆盖 9 道正例题 + 2 道无证据题 + 1 道实体陷阱题。

与另外两套评测的分工（三者平级，互不覆盖）：

| 体系 | 测什么 | 是否冻结 |
|---|---|---|
| `eval/` | 离线占位评测，`__TBC__` / `NOT_COMPARABLE` 阻断口径 | **冻结，不动** |
| `evalbench/` | 同一批文本样本在不同模型 / 提示词 / 参数下的表现（真实 API） | 独立演进 |
| `evalfmt/`（本目录） | **格式**换掉之后，解析保真、检索召回、引用准确、幻觉与拒答各是什么水平 | 独立演进 |

---

## 1. 怎么跑

```bash
# 只测检索层（秒级，零 LLM 费用）
python -m evalfmt.run_eval --mode lexical --answer off

# 全链路（真嵌入 bge-m3 + 真重排 + 真 LLM），约 1 分钟
python -m evalfmt.run_eval --mode vector --answer on
```

跑之前只要 PostgreSQL 起着（`.env` 里的 `WEBAPP_DATABASE_URL`）。脚本会：

1. 生成语料到 `evalfmt/corpus/`（确定性，重复生成字节一致）；
2. `DROP + CREATE` 独立 schema `eval_<mode>`，**不复用演示库**；
3. 自己拉起一个 uvicorn（端口 8771），跑完杀掉；
4. 上传 → 等解析 → 检索 → 生成 → 算分；
5. 写 `evalfmt/out/report_<mode>-<ret|ans>.md` 与 `.json`。

加 `--cleanup` 会顺手删掉上传文件并 DROP schema。`--base http://127.0.0.1:8765` 可直接打已有实例（此时不建 schema、不算保真率）。

为什么每次重建 schema：演示库里已有 80 多份历史文档，混在一起算召回率**不可复现**。同一套题两次跑出不同数字，那不是指标是噪声。

## 3. 四层指标（为什么不是一个「准确率」）

答错有四种完全不同的原因，混在一起就查不出问题在哪：

| 层 | 指标 | 定义 | 抓什么 |
|---|---|---|---|
| 解析 | **保真率** | 该文档的分块里，预埋事实的命中比例 | 字节 → 文本这一步有没有丢内容 |
| 检索 | **Recall@1/3/5** | 期望文档首次出现的名次 ≤ k 的比例（**文档级**） | 召回没召回 |
| 检索 | **MRR** | 首次命中名次倒数的均值 | 排在多靠前 |
| 引用 | **引用准确率@1** | top1 分块是否真的含答案事实 | 召回了但对不上 |
| 生成 | **答案正确率** | 期望事实出现在答案里 | 答对没答对 |
| 生成 | **幻觉率** | 无证据支持的事实型 token / 事实型 token 总数 | 编没编 |
| 生成 | **拒答正确率** | 无证据问题里，承认没找到且未编造的比例 | 会不会硬答 |
| 生成 | **陷阱违规率** | 把别的实体参数套上去的比例（越低越好） | 归错主体 |

事实型 token = 型号（`KX-2400`）、编号（`SN-88301`）、错误码（`E4711`）、
IP 等级（`IP54`）、IP 地址、带单位数字（`850W` / `24 个月`）。

## 5. 这套评估真正发现的三个问题（比 100% 更值钱）

**① 内网 IP 被当 PII 脱敏，工程文档因此不可检索**
`05-配网脚本.py` 的保真率一开始只有 50%：`10.66.8.1` 被脱敏成 `10.**.8.1`，
`DEFAULT_GATEWAY` 这个常量名在、值没了，这条事实等于不可检索。
内网/保留地址（10/8、172.16/12、192.168/16、127/8、169.254/16、100.64/10）是**拓扑信息不是个人信息**，
脱敏它只有代价没有收益。已修 `guardrails/detectors.py`（`_public_ipv4`），公网 IP 仍照常脱敏，加了单测锁定。

**② 词法门禁把跨语言召回掐死**
原实现是「先按词法筛候选，再在候选里做向量排序」。
中文问英文 PDF（"技术规范里的防护等级是多少？" vs `Protection grade: IP54`）零词法重叠
→ 该文档连进入向量排序的机会都没有 → 0 召回。
改成**门禁只判定「有没有可能相关」，不挑候选**：有词法信号且向量可用时，候选集放宽到全量。
词法完全无命中时仍返回空，`retrieval_empty` 降级语义不变（不硬凑）。
效果：Recall@1 从 77.8% → 100%。

**③ 评估指标自身也有 bug（两个）**
- 幻觉判定把**问题里复述的实体**算成编造（陷阱题被记成 40% 幻觉）。幻觉的定义是「说出无依据的事实」，
  不是「提到库里没有的名字」，已排除 question 内出现过的 token。
- 归一化没覆盖字形变体：期望 `320x210x95`，模型答 `320×210×95`（乘号），被判成答错。
  已补 `× → x` 等字形映射，**仍然不做模糊匹配**（`0.85kW` ≠ `850W`）。

三个问题里两个是**被评估抓出来的产品缺陷**，一个是**评估自身的缺陷**——
最后这个往往最危险，因为它会让人误信一份错的报告。

## 6. 口径与局限（面试如实说，别背成「准确率 100%」）

- **样本量太小**：9 道正例，1 题值 11 个百分点。100% 只能说明**链路通了**，不能说明系统强。
- **题目偏容易**：每份文档埋一个唯一事实，几乎等于「一个文档一道查找题」。
  真要做硬，需要：多跳（答案跨两份文档）、冲突文档（新旧版本数值不同，要选对）、
  表格数值计算（求和/求差）、长文档 needle-in-haystack（答案埋在 200 页里）。
- **召回率是文档级**：只判「期望文档在不在 top-k」，不看分块序号。分块级会更低，所以文档级不算高估。
- **幻觉率是规则级 grounding**：抽 token 查是否在证据里出现。
  它抓不到「有证据但归属错」——所以陷阱题单独一个指标，不混进幻觉率。
- **两个模式都要报**：只报 `vector` 会被问「基线呢」；只报 `lexical` 会被问「那你上向量干嘛」。
  33 个百分点的差距才是「向量到底值不值得」的答案。
- **图片目前检索不到**：`parsing/` 能识别（视觉 100%），但 webapp 主链路没接它。
  这是明确的未做项，写在 `docs/production/07-remaining-work.md`。
- **合成语料 ≠ 真实语料**：真实业务文档没有 ground truth，标注成本是这套方案落地的真实瓶颈。

## 7. 面试怎么讲（三段，90 秒）

> **第一段·发现**：我在上线前做多格式回归，10 份文档覆盖 txt/csv/yaml/pdf/图片/dxf。
> 结果 pdf 的两个问题全部召回失败，还有一份配网脚本的解析保真率只有 50%。
>
> **第二段·定位**：保真率那条查下去不是解析器的问题，是 PII 脱敏把内网 IP `10.66.8.1` 打成了 `10.**.8.1`——
> 规则本意是防个人信息泄露，但内网地址是拓扑信息，脱敏它只让运维文档不可检索。我改了判定：内网段放行，公网照旧。
> 召回那条是两阶段召回的结构性缺陷：词法门禁在向量排序**之前**筛候选，中文问英文 PDF 时零词法重叠，
> 文档连进入排序的机会都没有。我把门禁的职责改成「判定有没有相关信号」，不负责挑候选。
>
> **第三段·结论**：改完 Recall@1 从 66.7% 到 100%，幻觉率 0%，拒答 100%，陷阱 0%。
> 但我不会说「系统准确率 100%」——样本只有 9 题，一题值 11 个点，它证明的是链路通了，
> 不是系统强。要谈质量得先把多跳、冲突、数值计算这几类硬题补上，那才是真正的瓶颈。
