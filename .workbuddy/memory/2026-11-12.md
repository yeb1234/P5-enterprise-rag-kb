### 真实踩坑与修复（都留了前后对照）
1. **评分器假阴性**：v1 的 S07 模型已正确拒答，但固定关键词表没覆盖「无法基于上述资料回答」，
   判 0 分 → `METRICS@1.1.0` 改为「否定词 × 资料指代」组合判定；用 `rescore.py` 生成新 run，
   旧 run 完整保留，对照 `scoring_1.0_vs_1.2.json`（主指标 +0.1111）。
2. **指标饱和**：修正后 4 类全 1.0，无法区分配置 → `1.2.0` 新增 `answer_economy`
   （单行 / 不复述 / 不成段列表），不参与主指标，仅用于收敛对照。v1 基线仅 0.25。
3. **聚合 bug**：`by_model.avg_latency_ms` 被最后一个类别覆盖 → 修 `scoring.aggregate`，
   用 `rebuild_summaries.py` **只重建派生 summary**，records / config_snapshot 一字未动。
4. **多模型探测的归因错误**：`max_tokens=24` 时 6 个模型（含非推理型）全部空正文，
   原本误归因「推理模型专属」→ 修为网关侧共性，用 `--recompute` 只改解释、不改原始测量值。
5. **限流**：v1 首次 33/36、v4 首次 35/36，缓存续跑补齐到 36/36；两个失败 run 均保留为留痕。
6. **kimi-k2.6 模型级差异**：在带规则列表的提示词下会**整段复述 prompt**（S11/S12）、
   过度压缩漏答（S05/S10）。三步适配实证：temp=0 → 0.2（只救回噪声鲁棒，overall 0.861→0.945）
   → v3 few-shot（仍复述）→ 结论：不纳入默认选型，需输出复读检测（未实现，属后续工作）。
   另发现「复述 prompt 会把资料原文带进答案、骗过 `answer_accuracy`」，必须按维度联合判定。
7. `report.py --final-run` 只认 `=` 形式，README 写的是空格形式 → 已同时支持两种。
