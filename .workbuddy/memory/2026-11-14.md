## 关键事实与裁决（改动时别破）

1. **模型本来就是用户要的**：`.env` 早已是 `WEBAPP_LLM_PROVIDER=discovery` + `DISCOVERY_MODEL=deepseek-v4.1-flash-1017`。缺的是「低思考」。
   - 项目里**已有** `backend/app/core/config.py:69 DEEPSEEK_THINKING=disabled` 与 `backend/app/integrations/llm.py:52 payload["thinking"]={"type":"disabled"}`，本轮**沿用同一字段**，不另造 `reasoning_effort`。
   - webapp 侧新增 `WEBAPP_LLM_THINKING`（`WEBAPP_` 前缀隔离，避免与 backend 枚举同名污染）；`settings.thinking_disabled()` 是「是否低思考」唯一事实源，`providers.thinking_fields(disabled=...)` 是「低思考发什么字段」唯一事实源；流式 / 非流式 / 连接测试三条路径共用。
   - **诚实边界**：Discovery 网关是否识别 `thinking` 字段**未实测**。代码只报告「请求里带了什么」与 `usage` 里是否观察到 `reasoning_tokens`（`low_thinking_evidence`），不宣称已确认生效；不识别时由 `_filter_inline_think()` 兜底。
   - `get_model_label()` 返回值**不改**（`test_providers.py:40` 有断言）；档位单独用 `get_thinking_mode()` 暴露。
2. **限流最终裁定为三维计数** `RATE_DIMENSIONS = ("user","endpoint","model")`：依据用户任务 3 原文；任务 1 的部门是**统计**维度，不是限流维度。`rate_check(..., department=...)` 保留参数但**不参与计数**，只在命中结果里回传做成本归因。数据与规格文档一度按四维写，已按此裁决同步。
3. **统一 429 错误契约本轮落地**：`webapp/main.py` 的 `RATE_CODES` + `code/kind/message/trace_id/policy`，保留原扁平字段做兼容，新增 `X-RateLimit-Code` / `X-Trace-Id`；`app.js api()` 补 429 分支区分 `quota_exceeded`（不重试）与 `rate_limit_exceeded`（读 `Retry-After` 给等待秒数）。
   - 预算耗尽仍是 HTTP 200 + `{ok:false}`（阻断生效、错误码未统一）；`backend/app/core/constants.py` 的 `QUOTA_EXCEEDED→413` 本轮不动，登记为下期对齐。
4. **维度改造只改统计维度，不碰权限模型、不碰 backend 数据模型**：物理列名 `department_id`，维度名 `department`；`?dim=` 对外用物理列名。C22-3 四处配置键同批改完。`docs/org-model-change-plan.md` 的 13 步改造仍是**方案已定、代码尚未改造**。
5. **一个实测复现的真实缺陷（务必记住）**：`usage_events.department_id` 上的索引**不能写进 SCHEMA**。旧库执行 `executescript(SCHEMA)` 时还没有该列，`CREATE INDEX ... (department_id)` 会先抛 `no such column: department_id`，导致整个脚本失败、迁移函数根本跑不到。已把索引移到 `_migrate_tenant_to_department()` 末尾幂等创建，并用 `webapp/tests/test_department_migration.py` 锁定全新库 / 旧库 / 半迁移态三态。
   - 迁移函数用 `r[1]` 取 `PRAGMA table_info` 列名，**不依赖 `row_factory=sqlite3.Row`**（裸连接也要能跑）。
   - 半迁移态（两列并存）先 DROP 旧索引 → 用旧列有效值回填 `department_id`（`'default'` 视为未归因）→ `DROP COLUMN tenant`（老版本 SQLite 用 try/except 兜底）。
