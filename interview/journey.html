01

先说人话：每一层不加会出什么事

面试最容易被问「为什么要这个模块」。标准答法不是背技术名词，而是说清没有它会出现哪种具体故障。

模块一句话职责不加它，会出什么事面试一句
parsing/把 PDF / 图片变成结构化文本（块、表格、页码、置信度）扫描件进库就是乱码或空文本，检索全是噪声，模型只能编「解析质量是 RAG 的天花板，后面再强的模型也救不回一张被读错的表」
knowledge/判断哪些证据「适用」、哪些互相矛盾两份过期/冲突的文档被一起塞进上下文，模型随机选一个，答案不可复现「最新 ≠ 适用；冲突要按业务权威度裁决，不能交给模型即兴发挥」
cache/缓存派生结果、版本化失效、重启后恢复状态每次问答重算；重启后任务卡在 analyzing 永久不动「缓存 key 少一段就串权限；真值层必须先落盘」
guardrails/PII 与密钥的四出口防护身份证、手机号明文进日志、CSV 导出和向量库，展示层打码等于自欺欺人「一层规则、四个出口；只在一个地方打码等于没做」
showcase/左右分栏的解析工作台 + LLM 路由快照看不出解析好坏，也说不清「为什么这次用便宜模型、那次用 Pro 兜底」「左边分析、右边入库 JSON，参数一改就能看到结构变化」
webapp/可点击的演示切片（登录、上传、流式问答、badcase）面试只能看代码，没法现场演示闭环「离线可跑，admin/admin123 登录就能点完整流程」
backend/ + eval/生产骨架与评测体系只有功能没有量化，说不清「改完到底变好还是变坏」「先有评测集和基线，再谈优化」

一句话架构图（依赖只能单向）

showcase/ · webapp/ · backend/        ← 应用层，可以 import 下面的包
        │
        ├── parsing/     字节 → 结构化文本
        ├── knowledge/   证据适用性 / 冲突裁决
        ├── cache/       派生结果复用 / 版本失效 / 重启恢复
        └── guardrails/  PII 四出口
                ↑
        纯函数包之间不互相 import，也绝不反向 import 应用层
        （反向依赖一旦出现，包就没法单独测试、也没法单独复用）

面试可讲：依赖方向就是可测试性的保障。这四个包都能在零外部服务下跑单测（parsing 22 项 / knowledge 23 项 / cache 19 项 / guardrails 33 项）。

02

从 0 到现在的五段路

用户原话是「5 月用 v4.0 随便戳了戳，11 月用 4.1 再戳」。真实情况就是这样：前期是探索，后期是系统化。每一段都留下可验证的产物，而不是只留下聊天记录。

  1. 阶段 0 · 5 月 · 拿着 v4.0 随手戳
    把「企业知识库」从想法戳成一个能跑的骨架

    选型定了 React + FastAPI + PostgreSQL + Milvus + Redis/Celery + 外部 DeepSeek；先跑通「上传 → 分块 → 检索 → 生成 → 引用」这条主链。这个阶段最大的收获不是代码，而是知道自己不知道什么：分块怎么切、权限怎么收、评测怎么做，全是空白。

    留下：分层骨架、第一版 RAG、可运行 demo
  2. 阶段 1 · 11 月上 · 先补「怎么证明它好」
    评测体系与可观测，而不是继续加功能

    做了离线评测 harness（eval/）和真实 API 评估工作台（evalbench/），加了 badcase 采集闭环、限流与成本预算、审计台账。关键判断：没有基线就没有优化，功能再多也说不清好坏。

    留下：可复跑评测、badcase 闭环、成本与限流口径
  3. 阶段 2 · 11 月中 · 需求变更打回重想
    「不做多租户，改成单组织 + 多用户多部门」

    原本按多租户设计，后来明确改为部门树逻辑隔离。这件事没有硬改代码，而是先出13 步改造方案 + 35 条裁决，把「哪些查询必须走 ScopedRepository、哪些字段要删、缓存命名空间怎么改」全部写清。这也是一次面试素材：需求变了先改设计，不要边改边猜。

    留下：改造方案与裁决记录（方案已定、代码未全改，如实标注）
  4. 阶段 3 · 11 月中下 · 把四个能力拆成独立包
    解析、知识治理、缓存、内容安全各自独立

    每个包只做一件事、只依赖标准库、只有纯函数、配自己的单测。同时把模型换成 DeepSeek V4.1 Flash 并实测「低思考档」：thinking=disabled 让推理 token 从 55 降到 0、耗时约减半；而网关元数据里的布尔 reasoning 参数实测无效。

    留下：4 个可复用的纯函数包 + 一次「参数必须实测」的教训
  5. 阶段 4 · 11 月下 · 做能当场演示的东西
    解析工作台、LLM 路由快照、录像、上线指导、独立验收

    做了左右分栏的 showcase/：左边分析、右边入库 JSON、参数可调；LLM 路由按难度分流、每次选择生成单文件快照；录了 84 秒演示录像嵌进主解释页；写了阿里云上线指导；最后让 QA 独立验收，被查出 15 条缺陷（含 1 个 P0 密钥漏检），修完才敢说可演示。

    留下：可演示站点、录像、上线指导、验收报告与缺陷修复记录
03

架构到底在解决什么

架构不是画得好看，而是把「哪一层可以独立变化」划出来。下面每个决定都对应一个曾经真实发生或差点发生的问题。

① 为什么纯函数包不 import 应用层

一开始解析逻辑散在路由里，改一个阈值要起服务才能测。抽成 parsing/ 后，22 项单测 0.2 秒跑完，还能单独给别的项目复用。面试讲法：依赖方向决定可测试性；能纯函数化的就别放路由里。

② 为什么权限收敛到一个 decide()

权限判断散在多处时，最典型的故障是「列表接口过滤了、详情接口忘了」。收敛成纯函数后，越权红线可以写成 8 条断言（显式 deny 优先、跨部门拒绝、部门管理员覆盖子树、敏感度上限……），改权限只改一处。

③ 为什么「先过滤、再重排、再进模型」

先召回再过滤，意味着越权片段已经进了服务内存甚至缓存；一旦某条路径忘了复核，就会泄漏。所以顺序是：Milvus expr 先收窄 → 召回 → 逐条 decide() 复核 → 才进上下文。代价是多一次判定，收益是任何一路写错都不会把片段送进模型。

④ 为什么 PG 是真值、Redis 只是通道

进度、状态、策略如果只放 Redis，重启就丢。所以：文档状态写 PG，Redis 只负责推送；强停（SIGKILL）不执行关闭钩子，所以真值层必须先落盘。真实重启演练里 last_shutdown_at 确实没写进去，正好反证这一点。

⑤ 为什么缓存 key 要 13 段

每一段对应一类事故：缺 embedding 模型名 → 复用旧向量、余弦静默归零；缺 authz 快照 → 跨用户串权限；缺 data_version → 文档删了还返回旧片段。TTL 不是权限控制，写缓存前必须先按权限过滤。

⑥ 为什么 LLM 路由要带「单文件快照」

同一个问题，用便宜模型和 Pro 模型答案可能不同。如果只记「用了哪个模型」而不记提示词、参数、快照时间，就永远复现不了。所以每次路由选择生成一个 manifest，与入库 JSON 双向摘要互引：只改模型不改 manifest，对拍时立刻暴露。

05

踩过的坑（每个都是真实复现过的）

面试官最喜欢问「你遇到过什么难题」。答「没遇到」最减分；答「遇到过，这是现象、根因、修法和怎么避免」最加分。下面每条都能指到代码。

坑 1 · 幽灵向量

现象：删了文档，检索还能召回它的片段。

根因：删除只删 chunks，没删 chunk_embeddings。

修法：删文档前先删向量（源头治理）＋ 启动对账兜底。面试点：软删要成对删派生数据。
坑 2 · 重启后任务永久卡住

现象：服务重启，queued/analyzing 的文档再也不会动。

根因：队列活跃态只在内存里，进程一死就丢。

修法：启动扫描 documents.status 并幂等重投。面试点：可重建的状态不要持久化，要从真值重建。
坑 3 · 策略改完重启就回默认

现象：界面改了半衰期，重启又变回 90 天。

根因：策略写在 os.environ，只对当前进程有效。

修法：落 runtime_state，启动时恢复。面试点：配置要分清「进程内生效」和「持久生效」。
坑 4 · 只凭模型名判断「没有视觉能力」

现象：以为网关 10 个模型全是纯文本，准备放弃图片解析。

根因：只看模型名，没读 input_modalities 元数据。

修法：读结构化元数据 + 双图对照实测，发现 6 个支持 image。面试点：能力判定必须用元数据加实测，不能用命名启发式。
坑 5 · 流式输出把身份证整段发出去

现象：长文本逐字符输出时，脱敏后的回答里仍出现完整身份证。

根因：只保留尾部 24 字符，滑动窗口太短，永远看不到完整 18 位。

修法：找出横跨下发边界的连续候选串，把边界收缩到它的起点、整串扣住。面试点：流式脱敏的关键是边界，不是正则。
坑 6 · 版本号被瞬时状态污染

现象：同一份文件、同样参数，两次解析的 run_id 不一样，缓存和快照全失效。

根因：snapshot_version 把滞回计数 consecutive_hits 也算了进去。

修法：配置版本只由「模型/提示词/参数/档位」派生，决策实例另用 route_id。面试点：版本号要区分配置快照与运行实例。
坑 7 · 密钥正则漏掉连字符（QA 抓的 P0）

现象：sk-proj-… / sk-or-v1-… 这类真实密钥全部不被识别，还会被原样回显、落盘。

根因：正则字符集只写 [A-Za-z0-9]，在第一个连字符处截断。

修法：字符集纳入 - / _；A9 不再回显输入；A5 落盘前再兜底扫一次。面试点：安全规则要按真实凭证形态测，不能只测自己编的样例。
坑 8 · 共享状态串了用户

现象：为了让「连续 2 次才升档」生效，差点把路由状态做成全局单例，导致 A 的文件影响 B 的判断。

根因：滞回是跨调用状态，但隔离维度不是「进程」而是「文件 + 参数」。

修法：按 (source_sha, params_hash) 做 LRU，≤32 条，重启清零。面试点：有状态就要说清隔离维度与生命周期。
06

面试常问的 15 个问题

按主题分组。答案都刻意写短：面试是对话，不是背书；先给结论，再按追问展开。

架构与选型

1. 为什么选 FastAPI + PG + Milvus？

FastAPI 类型与 OpenAPI 天然贴合 AI 服务；PG 管业务真值与权限，Milvus 只管向量召回，不让向量库承担它不擅长的元数据过滤。被否决的方案：全放 ES（运维重、向量能力弱）、全放 Milvus（事务与权限难做）。

2. 为什么拆成这么多独立包？

因为它们的变化原因不同：解析换供应商、治理换策略、缓存换后端、安全换规则。拆开后各自单测 0.1–1 秒，且能单独复用。

3. 依赖方向为什么必须单向？

一旦纯函数包反向 import 应用层，它就不能脱离服务测试，也没法给别的项目用；更糟的是会出现循环依赖，改一处崩两处。

4. 演示切片和真实生产骨架差在哪？

SQLite 替 PG、进程内队列替 Celery、关键词打分替 Milvus。相同的是契约与失败语义：降级要留痕、权限要复核、真值要落盘。不同点我主动标注，不混着说。

权限与安全

5. 权限怎么做的？

收敛到纯函数 decide(subject, action, resource)：显式 deny 优先 → 精细粒度钩子 → 敏感度上限 → 可见范围（public / tenant / 同部门 / 部门子树 / owner）。列表和详情走同一套，避免「列表过滤了详情忘了」。

6. 先召回再过滤有什么问题？

越权片段已经进了内存甚至缓存；一旦某条路径漏了复核就泄漏。所以先按权限收窄 expr，召回后逐条再复核，双保险。

7. PII 为什么不做在展示层？

原文只要进了 chunks、向量、日志或 CSV，就总有一条路径把它带出去。所以是一层规则、四个出口：入库前、进模型前、输出前、日志导出前。

解析与检索

8. 扫描件怎么处理？

P0 先读容器头拿结构事实，质量门禁判「无文本层/低置信/表格不稳」，再逐页升级到视觉模型；最贵链路有页级预算闸门，超预算显式留痕并回退，不假装成功。

9. 90:10 是随机分流吗？

不是。它是上限/熔断线：正常文档 0% 触发，只有质量门禁命中才升级，最多 10% 的页。面试加分点：能说清「为什么不是按比例抽样」。

10. 两份文档冲突信谁？

不让模型自己挑。片段抽成 claim，按 key 分组、主题门控防误报，冲突图求连通分量后按簇裁决：业务权威度 → 生效期（强制需复核）→ 并列转人工。被淘汰的 claim 留痕不删除。

缓存与稳定性

11. 缓存 key 怎么设计？

13 段，每段对应一类事故：查询、embedding 模型、生成模型、top_k、检索模式、rerank、新鲜度、授权快照、数据版本、策略版本、schema 版本等。缺 authz 会串权限，缺 data_version 会返回旧答案。

12. 重启会丢什么？

分三类：可安全丢弃（限流窗口、SSE 连接）、可从真值重建（队列态、进度）、必须持久化（策略、预算、用量、文档、向量）。真值层先行，所以强停也不怕。

评测与上线

13. 怎么证明改动有效？

先有评测集与基线，再谈优化。离线 harness 保证可复现，真实 API 工作台看真实表现；不可比就标 NOT_COMPARABLE，不混着报数字。

14. LLM 怎么选型/分流？

按难度加权评分（页数、无文本层比例、表格量、置信度、是否需要 OCR、预算余量），双阈值滞回防抖动，难度持续高才升 Pro。每次选择生成单文件快照，模型/提示词/参数跟着走。

15. 上线要注意什么？

安全组只开 80/443 且 22 限来源 IP；密钥只走环境变量、不入镜像不入 Git；健康检查、日志轮转、回滚锚点（镜像 tag）；中国大陆节点对外服务要备案。实名/支付/备案只能本人做。

三条给「自学者」的实话

① 先能跑，再能讲。 每个功能都问自己「如果不加它会出什么故障」，答不上来说明还没懂。
② 主动标注没做。 面试官不怕你没做，怕你把没做说成做了；三态标注反而显得可靠。
③ 让第三方验收。 本项目最后一轮由 QA 独立复验，抓出一个 P0 密钥漏检——自己测自己，永远会漏。
