01

项目在干什么：一句话与四个角色

这不是「又一个 ChatGPT 套壳」，而是把企业文档变成可追溯答案的一条链路：上传 → 解析 → 入库 → 检索 → 权限 → 生成 → 引用 → 留痕。

它解决的问题

企业文档散在 PDF、扫描件、表格里，员工问一句话，系统要能找到依据、给出引用、说清不确定。 所以核心不是「生成得像人」，而是每条结论都能回溯到原文分块。

四个角色各自看什么

员工：问一句、看引用；部门管理员：看本部门队列积压、配额； 平台管理员：看审计、成本、限流；面试官：看边界、故障处理、可复跑证据。

03

14 个案例 · 点开看根因与面试问法

每条都是「可复现」的：给出现象、根因、修法，以及面试官可能怎么问。完整 MD 见 docs/case-studies.md。

安全 / 泄漏（5）

1API_KEY 正则漏了连字符，真实密钥全部漏检P0

现象 sk-proj-… / sk-or-v1-… 扫描 hits=0，A9 还回显原文、A5 落盘明文。

根因 字符集只写 [A-Za-z0-9]，密钥在第一个 - 处被截断；而我的测试样例是自己编的无连字符串，所以自测全绿。

修法 字符集纳入 -/_；A9 不回显输入；A5 落盘前整份 JSON 再扫一遍，命中即 422 且不写文件。

面试问法「你的规则怎么测的？」→ 用真实凭证形态测，别用自己编的样例。测试数据比测试代码更容易骗人。
2流式输出把身份证整段发了出去泄漏

现象 逐字符 SSE 输出长文本，脱敏后的回答里仍出现完整 18 位身份证。

根因 只保留尾部 24 字符，滑动窗口每轮只看前 2 字符，永远看不到完整 18 位。

修法 找横跨下发边界的连续候选串，把边界收缩到串起点、整串扣住；无 PII 文本流式拼接必须与原文逐字相同。

面试问法「流式脱敏怎么做？」→ 关键不是正则，是边界；标识符会跨 chunk，单块扫描必漏。
3伪造 X-Forwarded-For 就能绕过 IP 限流网关

现象 每次换一个 XFF，限流完全不生效。

根因 无条件采信 XFF 首值——这个头客户端可任意伪造。

修法 只有直连对端在 TRUSTED_PROXY_IPS 白名单内才采信 XFF 最左值；host 缺失返回 unknown，不落空串共桶。

面试问法「挂了 CLB/WAF 怎么拿真实 IP？」→ 信任链：只信自家代理 + 回源段白名单。
4未登录用户共用一个 anonymous 限流桶限流

现象 所有匿名请求 user 维度 key 都是 anonymous，要么全限死、要么阈值形同虚设。

根因 三维限流没有稳定身份时退化成同一个 key。

修法 加 IP 附加维度（600/60s），RATE_DIMENSIONS 仍三维；命中返回专用码 RATE_LIMIT_IP_EXCEEDED。

面试问法「多维限流怎么设计？」→ 分「业务配额」与「接入层防刷」，阈值、错误码、提示语都不同。
5/api/system/busy 不需要登录就能看到文件名鉴权

现象 未登录 200，且 active[].filename 是真实文档名。

根因 写的时候当成「状态查询」，没加登录依赖。

修法 加 Depends(get_current_user)；普通用户只拿计数 + redacted: true，文件名明细仅 admin。

面试问法「哪些接口要鉴权？」→ 判断标准是响应里有没有别人的信息，不是「是不是写操作」。

确定性与状态（3）

6版本号被「瞬时计数」污染，同参双跑 run_id 必变确定性

现象 同文件同参数两次，snapshot_version 从 7bd0a3fa 变 cb26b89a，run_id 全变。

根因 版本哈希里含 reason（"连续命中 1/2"）与 hysteresis（计数）——这是决策观测，不是配置快照。

修法 拆字段集：snapshot_version 只认配置（tier/model/prompt/params/…），route_id 用全字段。

面试问法「版本号里放什么？」→ 放配置，不放运行时计数；否则每次调用都产生新版本，缓存与对拍全失效。
7单次复杂档永远升不到 Pro（滞回状态每次新建）状态机

现象 难度 0.735（阈值 0.60），但每次都是 standard，Pro 永不触发。

根因 滞回要求连续 2 次命中，但每次请求都新建 TierState，计数永远 1/2。

修法 保留 k=2，按 (source_sha, params_hash) 做 LRU（≤32）缓存状态；不串用户、重启清零。

面试问法「有状态的东西怎么设计？」→ 隔离维度 / 生命周期 / 并发安全，三问答不出就是没设计。
8双向摘要互引在数学上无解一致性

现象 manifest 指向 ingest 的 sha256，ingest 又指向 manifest，怎么算都不对。

根因 对完整字节互签会形成循环依赖。

修法 签规范化投影：ingest 摘要剔除 manifest.sha256 后再算；两侧都可重算，篡改照样能拦。

面试问法「两个文件互校完整性？」→ 不可能对完整字节互签，要么单向、要么签剔除互引字段的投影。

配额与并发（3）

9全局预算：一个人烧光，所有人被拦配额

现象 预算只查 global，A 跑量用完后 B 的问答也被 policy=block 拦住。

根因 配额没按用户隔离，budgets 的 scope/key 只用了 global 一行。

修法 check_budget(user_id=) 优先用户级、回退全局；用户级花费按 usage_events.user_id 聚合。实测 A 拒、B 通。

面试问法「多用户配额怎么防互相影响？」→ 配额是每用户的、账也是每用户的；全局额度只作总闸。
10预算闸门只在离线评估里生效，问答链路根本没拦配额

现象 policy=block 时离线评估被拒，问答照跑。

根因 check_budget 只在 run_offline_eval 调用，chat_stream 从未调用。

修法 进模型前查一次；超支以 SSE 首事件告知（QUOTA_EXCEEDED）并写审计；离线评估保持 200 + {ok:false}，两种入口形态不同、语义一致。

面试问法「配额在哪一层拦？」→ 在真正花钱的那一层拦；只在报表里统计不算生效。
11并发闸把流式响应的令牌提前释放了并发

现象 并发上限 1，两个 SSE 同时进来第二个没被拒，并发数被低估。

根因 中间件 return response 时就 release()，而流式响应体是之后才发的。

修法 包装 body_iterator，try/finally 里流完再释放；正常/异常/断连三条路径都恰好一次。

面试问法「信号量何时释放？」→ 等响应真正结束；流式响应的 return 不等于结束。

工程与演示（3）

12Docker Compose v5 的 bake 在中文路径下直接失败构建

现象 docker compose up --build 报 x-docker-expose-session-sharedkey … non-printable ASCII。

根因 构建器把含中文的项目路径塞进 gRPC 头，编码失败。

修法 用 docker build + docker run 绕开；要用 compose 时加 COMPOSE_BAKE=false。同一镜像 run 完全正常。

面试问法「构建失败是环境还是代码？」→ 看同一产物换路径是否可用；镜像能跑、只有 compose 构建挂，就是构建器兼容问题。
13内嵌预览面板拦截 window.open 与 target=_blank前端

现象 按钮点了没反应，但直接访问 URL 是 200。

根因 WebView / 预览面板默认禁弹窗与新标签页。

修法 改 <a href> 同标签跳转，不依赖弹窗 API；地址写进 title 并在页面列出，可复制。

面试问法「为什么不用 window.open？」→ 它依赖弹窗权限，WebView / iframe / 企业微信内置浏览器都可能拦。
14演示种子被「启动自检」逐条消费演示

现象 造 130 条排队文档，重启几次只剩 50 条，继续减少。

根因 启动自检把所有 queued 幂等重投（正确的恢复行为），种子没有真实文件，重投后转 error。

修法 不改恢复逻辑，改演示策略：种子定位为「演示前生成、演示后清理」，docstring 写明会被消费。

面试问法「演示数据和正确性冲突怎么办？」→ 不要为演示改正确性逻辑，把演示数据降级为临时资产。
04

面试怎么讲：三层递进

同一个案例，讲得好与不好差在「有没有结构」。用 STAR 的变体：场景 → 现象 → 根因 → 修法 → 验证。

层次讲什么例子（案例 6）时长
一句话结论 + 影响「版本号里混进了运行时计数，导致同参双跑的 run_id 每次都变。」10 秒
一分钟现象 → 根因 → 修法补充「怎么发现的（对拍）」→「拆成配置哈希与决策哈希」→「改完后同参一致、改档必变」60 秒
追问级为什么这么修、还有什么坑「为什么不用时间戳做版本？因为不可复现」「多副本下 LRU 怎么办？换 Redis」按需

三个加分动作

① 主动说「我怎么发现的」——对拍、独立验收、真实形态测试，比「我写了测试」具体。
② 主动说「同类缺陷还会在哪」——比如密钥漏检之后，立刻问「其他规则是不是也只测了自己编的样例」。
③ 主动说「没做什么」——多副本限流未做、WAF 未标定、模型级 NER 未做，比吹完整更可信。
