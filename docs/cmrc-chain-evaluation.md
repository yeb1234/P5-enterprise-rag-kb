# CMRC2018 端到端链路评估

**日期**：2026-11-18 ｜ **分支**：未提交（工作区改动）
**对象**：`webapp/` 这套「上传 → 入库 → 检索 → 生成」链路，**不是**裸模型能力
**数据集**：CMRC2018 validation（CLUE 官方中文抽取式 QA，`hfl/cmrc2018`，hf-mirror 国内镜像，CC BY-SA 4.0）
**规模**：848 篇文档入池（948 chunk）、40 题提问、seed=42 可复现

---

## 0. 结论先行

**推荐配置：`top_k=4` + 分数阈值 `0.25` + rerank 按场景关（本数据集上无收益）**

| 组 | 配置 | 正确率 | 字符F1 | 答案字数 | Recall@k | MRR | rank1 | 上下文条数 | p50 | p95 |
|---|---|---|---|---|---|---|---|---|---|---|
| A | top4 / 无阈值 / rerank | 0.975 | 0.373 | 54.5 | 1.000 | 1.000 | 1.000 | 4.00 | 2002ms | 6234ms |
| B | top8 / 无阈值 / rerank | 0.975 | 0.368 | 55.8 | 1.000 | 1.000 | 1.000 | 8.00 | 2389ms | 11084ms |
| **C** | **top4 / 阈值0.25 / rerank** | **1.000** | 0.365 | 55.3 | 1.000 | 1.000 | 1.000 | **1.20** | 1973ms | 13653ms |
| D | top4 / 无阈值 / 关rerank | 0.975 | 0.376 | 54.1 | 1.000 | 0.988 | 0.975 | 4.00 | **1742ms** | 5813ms |

三条可落地结论：

1. **分数阈值是唯一有明确收益的参数**：上下文从 4.00 条降到 1.20 条（**-70%**），正确率不降反升（0.975 → 1.000）。
2. **top_k 4 → 8 是负收益**：正确率不变、答案更长、p95 从 6.2s 涨到 11.1s。
3. **rerank 在本数据集上无收益**：延迟降 13%，正确率不变，只让 1 题的 gold 从第 2 名掉到第 2 名（rank1 1.000 → 0.975）。

> 第 3 条**不能**推广成「rerank 没用」。CMRC 的问题与原文高度重合，Recall 全 1.0，重排没有可发挥的空间。项目另一份 nDCG 报告（检索型数据集，BM25 16.29% → bge-m3 33.93% → 重排 36.09%）才适合说明重排价值。

## 1. 系统链路验证（先证明能跑，再谈效果）

真实上传路径实测（隔离 schema，测完清理）：

| 步骤 | 结果 |
|---|---|
| `POST /api/docs/upload` 上传一份 153 字带表格的 Markdown | HTTP 200 |

| 提问「空压机维护周期多少天？负责人是谁？」 | 答「**180 天**，负责人是 **李工**」，来源命中 `维护手册.md` score **0.979** |

链路四段全部打通：上传 → 入库（真实分块）→ 检索（词法门禁 + bge-m3 + rerank）→ 生成。系统本身可用，不需要额外改造。

## 2. 数据集与抽样

| 项 | 说明 |
|---|---|
| 来源 | `hfl/cmrc2018` validation，CLUE 官方基准，国内 hf-mirror 镜像下载 |

| 为什么全量入池 | 先用 100 篇池试跑，Recall 仍 100%，无区分度；全量 848 篇才把检索放进「100 选 4」量级 |
| 同一 context 多问题 | 只取第 1 个，避免同一段文字被重复加权导致题目数虚高 |

## 3. 判分口径（含两处必要修正）

**主指标 `correct_rate` = 答案包含任一 gold 片段 或 字符F1 ≥ 0.7。**

第一版口径（整串 gold 子串匹配）实测 `contains=0.925`，逐条复核发现 **2 例是假阴性**：

| 题 | gold | 模型答案 | 误判原因 |
|---|---|---|---|
| 福林德斯大学在哪 | 澳大利亚南澳首府**阿德雷得** | 澳大利亚南澳首府**阿德莱德** | 音译差一字 |
| 现代货箱码头简称 | `现代货箱码头、现代货箱`（顿号拼接） | 简称"现代货箱码头"或"现代货箱" | 整串匹配失败 |

修正：
- gold 按 `、，,;；/｜| 以及 或` 拆成候选片段，任一命中即算包含；
- 增加 `F1 ≥ 0.7` 兜底，专治音译差异。

修正后 `correct_rate` 从 0.925 提到 0.975。**不用 EM**：模型输出是自然句，EM 会把几乎所有正确回答判成错。

## 4. 四个发现

### 4.1 无阈值时，第 4 名是随机片段

A 组（top_k=4、无阈值）40 题的**末位分数**分布：

| min | p25 | 中位 | p75 | max |
|---|---|---|---|---|
| 0.00000 | 0.0003 | **0.0006** | 0.0018 | 0.0214 |

**39/40 题的末位分数低于 0.01**。也就是说，第 4 条不是「相关度较低」，而是与问题无关的随机段落——它照样被拼进 prompt。C 组加上阈值后，这 3 条直接被砍掉，正确率反而升到 1.000。

### 4.2 答案冗长是 F1 低的主因，不是答错

- gold 答案长度：中位 **6 字**（最短 2 字）
- 模型答案长度：中位 **36 字**，均值 54.5 字，最长 287 字

典型例子：「氧化铁的化学式是什么？」gold `FeO`，模型答「根据参考内容，氧化铁（三氧化二铁）的化学式在参考 1 中写作 **FeO**（见[参考 1 · CMRC_037]）。不过该写法与常见化学式不一致，建议核对原文…」——**答对，但字符 F1 只有 0.083**。

所以字符 F1（0.37）与正确率（0.975）必须一起看，单看 F1 会得出「模型很弱」的错误结论。冗长本身是可优化项（prompt 约束「直接给答案，不超过 X 字」），但那是生成侧调优，不在本次参数范围内。

### 4.3 top_k 越大越差

B 组 top_k=8：上下文翻倍，正确率不变（0.975），答案反而更长（55.8 vs 54.5 字），p95 从 6.2s 涨到 11.1s。原因同上——多出来的 4 条几乎都是 0.00x 的噪声，只增加 token 和干扰。

### 4.4 rerank 在此数据集上测不出价值

D 组关掉 rerank：p50 从 2002ms 降到 1742ms（-13%），正确率不变，仅 1 题的 gold 从第 1 名降到第 2 名（仍在前 4，所以不影响最终回答）。

根因在数据集：CMRC 的问题几乎照抄原文（「《战国无双3》是由哪两个公司合作开发的？」），单路 bge-m3 已经排得很准，重排没有可纠正的排序错误。

## 5. 局限（与结论同等重要）

1. **40 题，1 题差异 = 2.5%**。0.975 与 1.000 的差距在统计上不显著，不能宣称「阈值提升 2.5%」；能说的是「阈值砍掉 70% 上下文而正确率没有下降」。
2. **检索维度饱和**：Recall@4 与 rank1 全为 1.000。**本报告不能证明检索能力强**，只能证明检索链路没坏。
3. **单一数据集、单一模型**（`deepseek-v4.1-flash-1017` + `bge-m3`）。换模型或换中文领域语料，结论可能变。
4. **字符 F1 系统性低估生成式答案**，报告以 `correct_rate` 为主指标，F1 只作横向对比用。
5. 848 篇入池时每篇平均 1.1 chunk，**测的是「文档级检索」而非「长文档段内检索」**。要测后者需要长文档语料（如技术手册整本）。

## 6. 顺带修掉的两个缺陷

| 缺陷 | 影响 | 修复 |
|---|---|---|
| `chunk_text` 纯字符滑窗（`text[i:i+800]`，step 720） | 89.6% 切点落在句中；48 块中 28 块表格被拦腰砍断（表头/分隔行/数据分属不同块）；相邻块 100% 重叠 80 字挤占 top-k | 改结构感知切分：标题/段落/表格/代码块为边界，表格整块保留（放宽至 4×size），标题必须绑定紧随正文 |
| `_observe_request` 缺 `+Inf` 桶键 | 任何耗时 >5s 的请求（大文档分析、冷启动检索）触发 `KeyError: inf`，把慢请求变成 500 | 初始化时预置 `math.inf: 0` |

分块改造后同文档实测：表格行截断 35→0、英文词截断 3→0、虚词结尾 2→0、重复标题块 0、**去空白字符 31210 = 31210（零丢失）**。

## 7. 复现

```bash
# A：基线（top4 / 无阈值 / rerank 开）
python webapp/eval_chain_cmrc.py --label A --doc-pool 848 --cases 40

# B：top_k=8
python webapp/eval_chain_cmrc.py --label B --doc-pool 848 --cases 40 --top-k 8

# C：阈值 0.25（推荐）
python webapp/eval_chain_cmrc.py --label C --doc-pool 848 --cases 40 --top-k 4 --threshold 0.25

# D：关 rerank（必须用 --rerank，环境变量会被 app_settings 表覆盖）
python webapp/eval_chain_cmrc.py --label D --doc-pool 848 --cases 40 --rerank off

# 改判分口径后不重跑模型、只重算
python webapp/eval_chain_cmrc.py --label A --rescore
```

产出：`webapp/out/cmrc_chain_{A,B,C,D}.json`、`*_records.jsonl`（逐题答案与来源可追溯）。

## 8. 下一步（按性价比排序）

1. **把阈值落地到 `rag.retrieve`**：`score >= max(top1*0.25, 0.02)`，收益确定、改动小。
2. **压生成侧的冗长**：prompt 加「先给答案，再给一句依据」，这是 F1 0.37 的真正短板。
3. **换长文档语料测段内检索**：当前 CMRC 单篇过短，测不出切分策略在长文档上的差别。
4. **如需检索侧的硬指标**，用 nDCG@k 在检索型数据集（T2Retrieval 类）上做，不要用 CMRC。
