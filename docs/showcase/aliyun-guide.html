2 · 逐步指导（在哪点 / 填什么 / 大概多少钱 / 常见坑）

金额说明

下面每步的「大概多少钱」都是 估算：0 元 = 该步骤本身不产生费用；其余均为「量级 + 假设」，实际以控制台实时价与你的用量为准，本文不提供精确报价。

2.1 注册 / 实名 / RAM

Step 1 注册阿里云账号 需你本人
在哪点
阿里云官网 www.aliyun.com → 右上角「注册」。也可用支付宝 / 钉钉扫码注册（会自动带部分实名信息，但仍需在阿里云侧确认）。
填什么
手机号 + 短信验证码、登录名、强密码（按页面规则）、勾选服务条款。注册后立刻绑定邮箱并开启 MFA 多因素认证。
多少钱
0 元（注册本身不收费）。
常见坑
注册时选择的「国家/地区」决定计费货币与税率且后续难改；支付宝已实名 ≠ 阿里云已实名，两套体系不自动同步；不要把密码/验证码发给任何人或贴进文档。
Step 2 实名认证（个人 vs 企业） 需你本人 · 不可代办
在哪点
控制台 → 「账号中心」→「实名认证」。购买中国内地地域云资源前必须完成，法律要求（《网络安全法》《反电信网络诈骗法》）。
填什么
个人：个人支付宝授权 / 扫脸，填姓名与证件号；企业：法人扫脸 / 企业支付宝 / 对公账户打款验证，需营业执照。一个账号只能选一种主体，认证完成后不可更改或解绑。
多少钱
0 元。差异在权益：个人只能开个人抬头普票、仅个人类活动；企业可开专票、可用短信/内容审核等企业专属产品、享企业活动。一个身份可认证账号数有限（公开资料口径 3~6 个不一，以控制台为准）；企业主体一般 10 个。
常见坑
个人认证用于企业场景，后续人员变动会出账号管理问题；平均约 20 分钟、最多 3 个工作日审核（流程说明，非承诺时长）；发票抬头默认跟随认证主体；14 岁以下不能认证。
Step 3 RAM 子账号与 AccessKey 最小权限 需你本人 策略可由 AI 起草
在哪点
控制台 → 「访问控制 RAM」→ 用户 / 权限策略 / 操作审计 ActionTrail。
填什么
为「部署脚本」单独建一个 RAM 用户，只授它需要的权限（如只读 ECS / 指定解析 API 的调用权限）；不要给主账号创建 AccessKey；一个应用一个环境一把 AK；设置 AK 闲置上限（建议 90 天内轮转）、配置来源 IP 限制、启用 MFA 与 ActionTrail 审计。更优做法是用 ECS 实例角色 + STS 临时凭证（无 AK 方案）。
多少钱
0 元（RAM / ActionTrail 基础使用通常不额外收费；以控制台为准）。
常见坑
AccessKey 是长期凭证，泄漏等于全账号资源受影响；严禁硬编码进代码、写进镜像、提交到 Git；AK Secret 只在创建时可完整查看，请自行保管在本人的密码管理器里，不要发给 AI。演示站若只跑离线解析，这把 AK 可以先不建。

2.2 ECS / 安全组 / 计费方式

Step 4 购买 ECS（演示站点建议配置） 需你本人支付
在哪点
控制台 → 「云服务器 ECS」→ 创建实例；或活动中心 / 轻量应用服务器。地域建议选离你近的中国内地节点（注意：内地节点才需要备案）。
填什么
建议配置（假设：单人演示、低并发、解析走外部 API、本地无数据库）：2 vCPU / 2~4 GiB 内存、系统盘 40 GiB ESSD、固定公网带宽 1~3 Mbps、镜像 Ubuntu 22.04 LTS 或 Alibaba Cloud Linux。密钥对登录优于密码登录。这是建议配置、非已采购、未经压测；解析若在服务端做重计算需上调规格。
多少钱
估算：按量常开为「数十元/月」量级；入门规格新用户促销常见「百元/年」量级（社区/活动页公开信息，非报价，活动随时变化）。以官网实时价为准。
常见坑
选错地域 → 备案规则与延迟都不同；忘记勾选公网 IP / 固定带宽 → 后面域名解析不了；系统盘太小 → 镜像与日志挤满；促销价常限首年/限购，续费价可能不同。
Step 5 按量付费 vs 包年包月（怎么选） 需你本人决定
在哪点
ECS 创建页「计费方式」；以及控制台概览「实例停机不收费」设置。
填什么
按量付费=后付费、按秒计，适合短期测试、可随时释放；包年包月=预付费、按月，适合 7×24 稳定服务，通常单价更优、常有新用户折扣。备案对实例时长/类型可能有前置条件（如要求包年包月且剩余时长充足），以备案页实时提示为准。
多少钱
估算：短期验证用按量更省（用完即释放）；打算挂几个月以上则包年包月更划算。均为相对量级，非报价。
常见坑
关机 ≠ 停费：包年包月关机仍计费；按量实例停止后计算费可停，但磁盘、EIP/公网 IP 仍计费，只有「释放实例 + 释放云盘 + 释放 EIP」才彻底停费；按量若忘记释放会持续扣到欠费。
Step 6 安全组（只放行必要端口） 需你本人 规则清单可由 AI 生成
在哪点
ECS 控制台 → 实例 → 「安全组」→ 入方向规则；规则即时生效，无需重启。
填什么
入方向：80/tcp 与 443/tcp 授权对象 0.0.0.0/0；22/tcp 授权对象只填你自己的出口 IP（形如 x.x.x.x/32），不要 0.0.0.0/0。不要把容器端口 8766 直接暴露公网——由 NGINX 反代到 127.0.0.1:8766 即可。出站默认放行。
多少钱
0 元。
常见坑
只改了安全组却忘了 ECS 内系统防火墙；把 22 全放开会被持续扫描爆破；把 8766 暴露公网等于把未鉴权的探测接口公开；修改了错误安全组（实例可能绑定多个）。

3 · 域名与 ICP 备案

为什么必须备案：按工信部规定，网站/互联网信息服务解析到中国内地（大陆）节点服务器并对外提供服务，必须先完成 ICP 备案；未完成即解析会被服务商监测系统识别并阻断访问。选中国香港/境外节点则无需工信部 ICP 备案（仍涉及公安联网备案等其他要求），但延迟、合规与计费口径不同——本页按内地节点写。

Step 7 域名注册 + ICP 备案 需你本人 · 需本人证件与人脸核验
在哪点
阿里云「域名」控制台注册域名；备案在 beian.aliyun.com / ICP 代备案管理系统。域名不在阿里云注册也可以，但需等待域名信息入库。
填什么
域名持有者信息必须与备案主体一致（不一致先过户）；填主办者/网站/服务器信息，上传证件、核验单、人脸核验，绑定「备案服务码」（ECS 实例会自动生成，一台实例可申请若干个，以控制台为准）。备案成功后在页脚展示 ICP 号，并在 30 日内完成公安联网备案。
多少钱
估算：域名年费为「几十~百元/年」量级（后缀差异大）；备案服务本身免费。均非报价，以官网实时价为准。
常见坑
备案流程时长是说明、不是承诺：阿里云初审约 1~2 个工作日 + 电话核验 → 工信部短信核验（收到后 24 小时内本人完成）→ 管局审核约 1~20 个工作日，整体公开口径约 3~22 个工作日，各地不同；备案订单有效期有限，超期会被清理；教育/新闻/医疗等特殊行业需前置审批。
没有域名时的临时验证方案（及其限制）

可先用 ECS 公网 IP + HTTP + 80 端口 做纯技术验证（容器能起、/health/live 能通、页面能打开）。限制：① 内地节点未备案的域名解析会被阻断，IP 直连访问通常也不作为正式对外服务方式，且随时可能受限；② 无域名无法签发常见 DV 证书，做不了正式 HTTPS；③ 浏览器会标「不安全」，涉及登录/Cookie 的功能不可靠；④ 只适合你本人短时间自检，不能当作上线。想长期稳定对外，就走完域名 + 备案。

4.1 安装 Docker 与构建镜像

bash · ECS 内首次准备

sudo apt-get update
sudo apt-get install -y ca-certificates curl gnupg nginx

bash · 把最小部署单元弄上 ECS（二选一）
# 方式 A：本地打好镜像，scp 传 tar 上去再 load（无需在服务器放源码）
docker build -f Dockerfile.parse -t parse-demo:v1 .
docker save parse-demo:v1 | gzip > parse-demo-v1.tar.gz
scp parse-demo-v1.tar.gz root@<ECS公网IP>:/opt/
ssh root@<ECS公网IP> 'docker load < /opt/parse-demo-v1.tar.gz'

# 方式 B：只上传必要文件，在 ECS 上构建（context 为项目根，只 COPY parsing/）
scp -r Dockerfile.parse parsing/ .env.prod root@<ECS公网IP>:/opt/parse-demo/
ssh root@<ECS公网IP> 'cd /opt/parse-demo && \
  docker build -f Dockerfile.parse -t parse-demo:v1 .'
别把主干项目带进来

仓库根目录的 docker-compose.yml 默认是 11 个服务的完整演示环境（PG/Redis/Milvus/MinIO/Celery…），不要在服务器上直接 docker compose up -d。解析站是独立最小单元：要么用上面的单镜像 docker run，要么只起 parser 一个服务：docker compose --profile parsing up -d --build parser。

bash · 启动容器（密钥走 --env-file，端口只绑本机）
cd /opt/parse-demo

  -p 127.0.0.1:8766:8766 \

4.2 NGINX 反向代理与 HTTPS

nginx · /etc/nginx/conf.d/parse-demo.conf（HTTP 阶段）
server {
    listen 80;
    server_name <你的域名>;
    client_max_body_size 32m;          # 上传文件大小，按演示需要调

    location / {
        proxy_pass http://127.0.0.1:8766;   # 同源静态页 + API 都在容器里
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        # 解析/流式响应可能较慢，放宽读超时；SSE 场景需关缓冲
        proxy_read_timeout 120s;
        proxy_buffering off;
    }
    location /health/ { proxy_pass http://127.0.0.1:8766/health/; }
}

保存为 /etc/nginx/conf.d/parse-demo.conf 后执行 sudo nginx -t && sudo systemctl reload nginx（这条是 shell 命令，不要粘进上面的 conf 文件）。

HTTPS 证书（两条途径，都需 你本人 在控制台/域名 DNS 处验证）

途径 A · 阿里云免费个人测试证书：控制台 →「数字证书管理服务」→「个人测试证书（原免费证书）」→ 0 元领取 → 创建证书填单域名 → DNS 验证（域名在阿里云可选自动 DNS 验证，否则手动加 _dnsauth TXT 记录）→ 下载 Nginx 格式（pem + key）。公开资料显示：DV 单域名、每实名主体每自然年约 20 张、有效期约 90 天、年底未用额度清零、不支持通配符与部分特殊后缀、官方标注仅供测试/个人试用。坑：90 天到期要重新申请并替换，务必设日历提醒（或写续期脚本）。
途径 B · Let's Encrypt + certbot：sudo apt install certbot python3-certbot-nginx → sudo certbot --nginx -d <你的域名>，90 天有效期、自动续期任务，用 sudo certbot renew --dry-run 验证。两者都要先有已备案且解析生效的域名。

nginx · HTTPS 阶段（证书到位后，直接由 certbot 生成或手写）
server {
    listen 80;
    server_name <你的域名>;
    return 301 https://$host$request_uri;          # HTTP → HTTPS
}
server {
    listen 443 ssl http2;
    server_name <你的域名>;
    ssl_certificate     /etc/nginx/tls/<你的域名>.pem;
    ssl_certificate_key /etc/nginx/tls/<你的域名>.key;
    ssl_protocols TLSv1.2 TLSv1.3;
    # 全站 HTTPS 稳定后再考虑 includeSubDomains，先只用基础 HSTS
    add_header Strict-Transport-Security "max-age=31536000" always;
    add_header X-Content-Type-Options nosniff always;
    add_header Referrer-Policy strict-origin-when-cross-origin always;
    client_max_body_size 32m;
    location / {
        proxy_pass http://127.0.0.1:8766;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
        proxy_buffering off;
    }
    location /health/ { proxy_pass http://127.0.0.1:8766/health/; }
}

4.3 环境变量 / 密钥 / 开机自启

.env.prod · 只放在服务器上，绝不入镜像 / Git
# /opt/parse-demo/.env.prod  权限 600，属主 root
# 演示起步建议全部留空/关闭外部调用 → 纯离线解析，0 元
PARSING_STRATEGY=auto
PARSING_OFFLINE=1
PARSING_VISION_ENABLED=0
PARSING_VISION_API_KEY=
PARSING_OCR_API_KEY=
DISCOVERY_API_KEY=
# 需要外部 LLM/视觉兜底时，由你本人决定是否开通并把 Key 填在这里
# 注意：这些 Key 是第三方 API 凭证，不是阿里云 AccessKey；
# 若用阿里云文档解析 API，其 RAM AccessKey 同样只放这里，不要硬编码
密钥三条铁律

① 绝不入镜像：不要 COPY .env*、不要 ENV KEY=...；Dockerfile 里只放代码。② 绝不入 Git：服务器上的 .env.prod 与仓库的 .env 都要在 .gitignore 内；提交前用 git grep -nE 'sk-[A-Za-z0-9]{20,}' 扫一遍。③ 绝不进聊天窗口：不要把 Key 发给 AI、贴进工单或截图。轮换顺序：生成新 Key → 更新 .env.prod → 重启容器 → 验证 → 在供应商侧吊销旧 Key → 记一笔变更。

bash · 权限 / 开机自启 / 日志
chmod 600 /opt/parse-demo/.env.prod
# 开机自启：容器已带 --restart unless-stopped；Docker 服务本身也要开机起

5 · 费用估算表（估算 + 假设前提，不是账单）

统一假设：① 单人演示、日均 100 次解析、每次 2 页 → 约 6000 页/月；② 一台入门 ECS 常开 1 个月；③ 一个普通域名；④ 用免费 DV 证书；⑤ 30 天/月。所有数字为按假设推算的估算值，实际取决于是否接通外部 API、降级策略、缓存/重试、促销与实时单价；以官网实时价为准。

6.3 常见故障排查

现象排查顺序
端口不通 / 页面打不开① 安全组入方向是否放行 80/443；② ECS 内 ss -lntp | grep -E '80|443|8766' 与系统防火墙；③ 容器是否 -p 127.0.0.1:8766:8766（只绑本机是对的，靠 nginx 反代，别直接公网连 8766）；④ nginx -t 与 proxy_pass 目标；⑤ 备案是否生效（内地节点未备案会被阻断）。
备案未生效 / 域名被阻断查 ICP 代备案系统状态；确认域名持有者与备案主体一致；工信部短信核验是否在 24 小时内完成；域名的 A 记录是否指向正确的 ECS 公网 IP；临时用 IP+HTTP 只做技术自检，别当上线。
跨域（CORS）报错本方案是同源静态单页，正常无跨域；若把前端分离部署，需在服务端配 CORS 白名单，且 allow_credentials 时不能用 *；更推荐统一走 NGINX 同源反代。
密钥缺失 / 解析报鉴权错docker exec parse-demo env | grep -E 'PARSING|API_KEY' 看注入是否生效；确认 --env-file 路径与换行格式；区分「离线模式未开外部调用」与「Key 真的没配」；不要为排错把 Key 打进日志。
容器重启后丢环境变量用 --env-file / compose 文件固化，别只靠交互式 -e 或 shell export（重建容器即丢）；确认 .env.prod 没被清理脚本删掉；docker inspect 核对 Env；同时确认 --restart unless-stopped 与 systemctl enable docker。
超时 / 大文件上传失败NGINX proxy_read_timeout 与 client_max_body_size；解析链路自身超时（仓库默认 PARSING_VISION_TIMEOUT_S=60）；上游网关/外部 API 超时；SSE 场景必须 proxy_buffering off；必要时把长任务改异步 + 进度查询。
