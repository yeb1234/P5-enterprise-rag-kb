# Phase 1 需求范围与两档演示剧本

> **文档定位**：`showcase/` 独立演示站点的**范围定义文档**（本轮唯一产出），供 Phase 2 spec 与实现方使用。项目本体仍是「企业内部知识库 RAG 开发框架骨架 + 可运行演示切片」，**不是上线交付版**。
> **本轮交付边界**：只新增本文件 `docs/showcase/01-scope.md`；不改任何源码、不改 `webapp/` 行为、不改任何既有文件、不动冻结区 `eval/` 与 `demo/`。`showcase/` 站点、录像、主解释 HTML 内嵌、上线指导 HTML 均**未做**，本文件只定义它们该长什么样。

> **数字纪律**：不编造实测数字。本文所有时长、阈值、默认值均标注为「建议」或「待实现方确定」，不作为实测结论；录像时长建议区间来自主理人派单要求。
> **事实源**：主理人已确认的事实直接采信，不重新论证；本轮另实查确认 `parsing/router.py`、`parsing/strategies/{local,ocr_api,multimodal}.py`、`parsing/contracts.py`、`interview/index.html` 存在，`docs/showcase/` 原为空目录。

## 1. 一句话项目定义与可量化成功标准

### 1.1 一句话定义

> 在**离线可跑**的独立 `showcase/` 站点里，用「左分析 / 右入库 JSON」同屏对照，把 **文本 PDF 与图片（或扫描页）两类文件**的解析结果和参数调节效果讲清楚；用**简单 / 复杂两档**演示覆盖本地策略与视觉升级 + Pro LLM 兜底，并把 **60–90 秒录像**与功能介绍嵌进 GitHub 风格单文件主解释页，另出一页阿里云上线指导。

## 2. 用户画像与核心用户旅程

### 2.1 三类画像

| 角色 | 来看什么 | 最在意的证据 | 最容易被扣分的点 | 对应档位 |
|---|---|---|---|---|
| 评审方（AI Agent 工程师 / FDE 岗） | 能不能在 2 分钟内讲清「解析 → 分块 → 入库 → RAG」的取舍 | 参数改动引起 JSON 变化、三级策略升级链、快照单文件把 LLM 与提示词版本绑在一起 | 把 `只设计` 说成 `已实现`；把离线兜底说成实时在线视觉识别 | 简单档开场 + 复杂档收尾 |
