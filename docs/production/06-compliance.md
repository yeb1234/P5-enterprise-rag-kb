# 06 · 备案 / 证书 / 等保：三件事的科普

> **给谁看**：第一次要把站点放到公网、被「ICP 备案」「SSL 证书」「等保」这些词绕晕的人。
> **本文定位**：**流程科普 + 对照指南**，不是法律意见，也不是已办理证明。
> **三态**：本文所有条目均为 **未做（流程指南）**——项目是演示切片，没有办理任何备案/证书/等保。
> **数字纪律**：耗时与费用一律写「量级 / 区间，以官方与服务商实时为准」，**不编具体报价**。

---

## 1. 一句话分清三件事

> **ICP 备案** = 网站**能不能开**（准入）。
> **HTTPS 证书** = 传输**加不加密**（技术）。
> **等保** = 安全**达不达标**（合规等级）。

三者互相独立，**办了一个不等于办了另一个**。下面这张表建议先看：

| 对比项 | ICP 备案 | HTTPS 证书 | 等保（等级保护） |
|---|---|---|---|
| **管什么** | 网站主体与内容的合法准入 | 浏览器与服务端之间的传输加密 | 系统整体安全能力是否达到某个等级 |
| **谁要求** | 工信部（管局）/ 依据《互联网信息服务管理办法》 | 无强制，但浏览器与用户预期事实上要求 | 公安部体系 / 《网络安全法》要求网络运营者履行等级保护义务 |
| **不办会怎样** | 用中国大陆服务器对外提供网站服务时，**80/443 会被阻断**，无法正常访问 | 浏览器标「不安全」；登录/Cookie 场景不可靠；部分客户端直接拒绝 | 监管检查时可能被要求整改/处罚；客户（尤其政企）招标常作为硬门槛 |
| **大概耗时** | 服务商初审 1~2 工作日 + 短信核验（24 小时内）+ 管局审核约 1~20 工作日，整体常见 **3~22 个工作日**（**流程说明，非承诺**） | 免费 DV 几分钟~数小时；OV/EV 需人工审核，数个工作日量级 | 从定级到测评完成，常见 **1~6 个月**量级，取决于整改量 |
| **花钱量级** | **备案本身免费**（域名另计，几十~百元/年量级） | 免费证书 0 元；付费 DV 百元/年量级；OV/EV 千元~万元/年量级 | 测评费万元量级起（估算，以测评机构报价为准）+ 整改投入视差距 |
| **谁办** | 你本人（主体证件、负责人人脸核验） | 你本人（域名验证） | 企业主体 + 测评机构 |

**记忆锚点**：备案是**门槛**，证书是**锁**，等保是**体检报告**。

## 2. ICP 备案（网站准入）

### 2.1 什么情况必须办

- **必须办**：服务器在**中国大陆**节点，且**对外提供网站/互联网信息服务**（哪怕是演示站，只要用域名对公网开放）。
- **不需要**：服务器在**中国香港 / 境外**节点（无工信部 ICP 备案要求，但仍需注意当地法律与公安联网备案等其他要求）。
- **常见误区**：「用 IP 直接访问就不用备案」——技术上能通，但内地节点未备案的对外服务随时可能被阻断，不能作为正式方案；且无域名基本签不了常规 DV 证书。

### 2.2 个人 vs 企业

| | 个人备案 | 企业备案 |
|---|---|---|
| 主体 | 自然人 | 公司/个体户/组织 |
| 材料 | 身份证、负责人人脸核验、手机号 | 营业执照、法定代表人信息与核验、负责人信息 |
| 适用 | 个人博客、内部演示站 | 企业经营性网站、对外业务系统 |
| 关键限制 | **不能用于企业经营性网站**；网站内容需与个人性质相符 | 网站性质需与经营范围相符；部分行业需**前置审批** |

> 关键点：**备案主体要与网站性质一致**。用个人主体备案企业站，后续经营、开票、被核查都会出问题；反之企业主体备案个人内容也可能被要求说明。
> 域名持有者信息需与备案主体一致，不一致要先过户。

### 2.3 流程（以主流云厂商为例）

1. **准备**：买好符合备案要求的云服务器（有公网 IP）→ 注册/持有域名（持有者=备案主体）→ 准备证件与核验材料。
2. **提交**：在服务商的备案系统填主体信息、网站信息、服务器信息，绑定「备案服务码」（由云服务器实例生成，一台实例可申请若干个，以控制台为准）。
3. **服务商初审**：约 1~2 个工作日，通常会**电话核验**真实性。
4. **工信部短信核验**：收到短信后需在 **24 小时内**本人完成核验，超时会退回。
5. **管局审核**：约 1~20 个工作日（各地不同），通过后下发**备案号**。
6. **上线后**：在网站页脚展示 ICP 备案号并链接到工信部查询页；并在 **ICP 成功后的 30 日内**完成**公安联网备案**（这是**另一件事**，不等于 ICP 备案）。

> **时效提醒**：备案订单通常有有效期（如 45 天），超期会被清理，需重新提交。上述时长是**公开流程说明，不是服务承诺**，以属地管局实际审核为准。

### 2.4 不备案的真实后果

- 内地节点未备案 → 服务商监测到会**阻断 80/443 访问**，表现为「域名解析正常但打不开」。
- 排查口诀：先查备案状态 → 再查 DNS 解析 → 再查安全组。三者顺序错了会白折腾。

## 3. HTTPS 证书（传输加密）

### 3.1 DV / OV / EV 的区别（只讲验证强度与适用场景，不排名）

| 类型 | 验证什么 | 签发速度 | 典型适用 |
|---|---|---|---|
| **DV**（域名验证） | 只验证**你能否控制这个域名**（DNS/文件/邮件验证） | 分钟~小时级，可自动 | 个人站、演示站、API、内部工具 |
| **OV**（组织验证） | 额外验证**组织真实存在**（营业执照等） | 数个工作日（人工） | 企业官网、对外业务，需在证书里体现组织信息时 |
| **EV**（扩展验证） | 更严格的组织与法律实体核验 | 更长（人工） | 金融、支付等对信任背书要求高的场景 |

> 现实提醒：现代浏览器**已不再为 EV 显示特殊「绿条」**，EV 的可见差异主要是证书详情。选型应按「是否需要组织信息背书 / 客户是否要求」决定，而不是按「看起来更高级」。

### 3.2 免费 vs 付费

| | 免费证书 | 付费证书 |
|---|---|---|
| 代表 | Let's Encrypt、云厂商免费 DV（如阿里云个人测试证书、腾讯云免费 DV） | 商业 DV/OV/EV |
| 有效期 | **约 90 天**，必须续期 | 1 年或更长 |
| 关键差别 | **必须做自动续期**；通常只支持单域名、不支持通配符（视厂商）；无人工客服；官方多标注「适合测试/个人」 | 更长有效期、可通配符、有服务与赔付条款、可体现组织信息 |
| 成本 | 0 元 | 百元~万元/年量级，视类型与品牌 |

### 3.3 自动续期（最重要的一件事）

免费证书 90 天有效期，**忘记续期 = 到期当天全站 HTTPS 失效**，这是最常见的事故之一。

```bash
# Let's Encrypt + certbot：安装后证书会自动写续期任务
sudo certbot --nginx -d example.com -d www.example.com
# 验证续期能成功（不会真的改证书，只演练）
sudo certbot renew --dry-run
# 确认定时任务存在（systemd timer 或 cron）
systemctl list-timers | grep certbot    # 或 crontab -l | grep certbot
# 续期成功后要 reload 反向代理，否则进程仍用旧证书
sudo nginx -t && sudo systemctl reload nginx
```

云厂商免费 DV 一般在控制台「下载证书 → 重新上传/替换 → 重新绑定」；部分产品支持托管自动续期与自动部署，**开通前先确认是否含自动续期**。

### 3.4 证书链不完整的常见现象

- 现象：浏览器显示「不安全/证书无效」；`curl` 报 `SSL certificate problem: unable to get local issuer certificate`；部分老版本 Android/Java 客户端握手失败，而桌面 Chrome 却正常（因为浏览器会自动补中间证书）。
- 原因：只部署了**站点证书**，漏了**中间证书**。
- 排查与修复：
  ```bash
  # 看服务端实际下发的证书链（应有多张）
  openssl s_client -connect example.com:443 -servername example.com -showcerts </dev/null 2>/dev/null | grep -E 'BEGIN CERTIFICATE|s:'
  # 结论：链里只有 1 张 → 缺中间证书；应使用厂商提供的 fullchain.pem
  ```
  配置里 `ssl_certificate` 指向 **fullchain（站点证书 + 中间证书）**、`ssl_certificate_key` 指向私钥，不要只填站点证书。

## 4. 等保（网络安全等级保护）

### 4.1 一句话定义

对网络系统按**重要程度分级**，要求运营者按对应等级落实**技术与管理**安全措施，并由**有资质的测评机构**验证是否达标——是**体系性合规**，不是买某个产品。

### 4.2 二级 vs 三级（适用情形）

| | 二级 | 三级 |
|---|---|---|
| 常见适用 | 一般企业内网系统、普通对外业务系统、影响范围有限的系统 | 涉及**大量公民个人信息**、关键业务、一旦被破坏会造成严重社会/经济影响的系统；很多政企/医疗/金融客户要求三级 |
| 监管强度 | 备案 + 定期测评 | 备案 + **更严格**的测评与监督检查，通常每年测评 |
| 测评频率 | 多为两年一次（以属地公安要求为准） | 通常每年一次（以属地公安要求为准） |
| 投入 | 相对可控 | 明显更高（技术+管理制度+审计+备份+应急） |

> **定级由谁定**：由运营者依据业务影响**自主定级**，必要时专家评审；**不是**自己随便选一个等级，也不是「越高级越安全越好」——等级错配会导致成本浪费或合规不足。

### 4.3 流程（五步）

```
定级 → 备案（公安）→ 建设整改 → 等级测评 → 监督检查（持续）
```

1. **定级**：确定系统边界与受侵害客体，得出等级（二级/三级…）。
2. **备案**：到属地公安机关备案（提交定级报告等材料）。
3. **建设整改**：按等级要求补齐技术措施（身份鉴别、访问控制、审计、入侵防范、数据备份与恢复等）与**管理制度**（安全责任制、人员管理、应急预案）。
4. **等级测评**：委托有资质测评机构出具测评报告；不达标则整改后复测。
5. **监督检查**：监管抽查 + 定期测评，**持续**维持，不是一次通过就结束。

### 4.4 耗时与成本（估算，非报价）

- 耗时：从启动到首次测评通过，常见 **1~6 个月**量级，取决于现状与整改量；三级通常更久。
- 成本：**测评费**万元量级起（按系统数量、等级、机构报价）；**整改投入**可能远大于测评费（设备、制度、人力、日志留存等）。**均为估算，以实际报价为准**。

## 5. 常见误区（每条给纠正）

| 误区 | 纠正 |
|---|---|
| 「有 HTTPS 就安全了」 | HTTPS 只保证**传输**加密。注入、越权、弱口令、密钥泄漏、越权访问数据，HTTPS 一个都防不住。安全是**鉴权 + 输入校验 + 最小权限 + 审计 + 补丁**的组合。 |
| 「备案 = 等保」 | 完全不同：备案是**准入**（能不能开），等保是**安全达标**（达不达标）。备案成功不代表安全合格，等保通过也不替代备案。 |
| 「买了 WAF 就合规了」 | WAF 只是**技术措施之一**。等保要看技术+**管理制度**+人员+审计留存+备份恢复+应急演练，且需要**测评机构**验证。 |
| 「等保是一次性的」 | 定级备案后要**定期测评 + 监督检查**；系统重大变更（架构、边界、业务）可能需重新定级或重新测评。 |
| 「个人不能备案企业站」 | 准确说法：**备案主体必须与网站性质一致**。个人主体不能用于企业经营性网站；企业站应以**企业主体**备案。个人可以正常备案个人性质的站点。 |
| 「域名注册了就能用」 | 域名注册 ≠ 备案。内地节点对外服务还需 ICP 备案；域名持有者信息要与备案主体一致。 |
| 「公安备案和 ICP 备案是一回事」 | 两件事：ICP 备案在工信部体系（管局），公安联网备案在公安体系，且通常在 ICP 成功后 30 日内办理。 |

## 6. 与本项目的关系

- **演示切片本身**：不需要备案/证书/等保——它跑在本机或内网，不对公网提供服务。
- **一旦要对外**（用域名 + 内地服务器对外提供访问）：
  1. **ICP 备案是前置**（否则打不开）；
  2. **HTTPS 证书是必须**（登录、Cookie、用户信任）；
  3. **等保看客户与行业**：个人演示不需要；一旦是政企/医疗/金融客户的正式系统，招标与验收常要求二级或三级。
- **本项目已具备的可复用基础**（真实存在，不是规划）：审计只追加（`audit_logs`）、权限单一判定入口（`decide()`）、限流四维 + 并发闸、用户级预算、密钥外置（`.env` 不入库）。这些是等保「访问控制/安全审计/入侵防范」方向的**技术素材**，但**离等保达标还有明显差距**：缺集中日志留存与检索、缺备份恢复演练、缺制度与应急预案、缺测评。**不要把现有实现说成等保达标**。
