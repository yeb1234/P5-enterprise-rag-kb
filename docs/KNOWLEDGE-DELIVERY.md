## 2. 三段话术（照着念）

**开场（30 秒）**
> 这次补的是 RAG 里最容易被追问的两块：文档入库之后会过期、会彼此矛盾。我把它做成独立的知识治理层：先用时间衰减和适用性门控决定「哪些证据现在有效」，再把检索到的片段抽成 claim，按冲突图分簇裁决，最后给生成层一份结构化证据记录。

**技术深度（90 秒）**
> 新鲜度不是 `ORDER BY created_at DESC`。最新不等于适用——未来生效的政策要排除而不是判过期，旧合同可能仍适用于特定群体，不同地区的同一字段取值不同也不算冲突。有效分是 `相关分 × (1 - blend + blend × 0.5^(年龄/半衰期))`，每个数都能在前端表里手算复核。
> 冲突检测我用的是规则级 claim 比对：归一化数值、单位、否定词，过滤年份和裸小整数防误报，再用并查集求冲突图连通分量，**每个簇独立裁决**。裁决顺序是业务权威度 → 生效期（但强制人工复核）→ 无法裁决就并列两个版本转人工。相似度最高不等于可信，向量分数里根本没有权威度和生效期。
> 最关键的一条：**冲突是正式状态**。`EvidenceRecord.conflict_signal` 会明确告诉生成层「这里有两份互斥证据」，不能把片段无序塞进上下文赌模型选对。

**诚实边界（30 秒）**
> 这是规则级实现，不是 NLI 模型级矛盾识别；合成场景是功能可演示的证明，不是质量基线。真实检索链的新鲜度重排我默认关掉（开关可控），只在 top_k 内重排——生产应该在召回前用 SQL / Milvus expr 做硬过滤。生成层注入证据记录目前仍只设计未做，权威注册表的业务审批流也没做。我不把「能连通」说成「具备生产质量」。

## 3. 现场演示 5 步（约 3 分钟）

1. `python -m uvicorn webapp.main:app --port 8765`，`admin / admin123` 登录 → 侧栏「知识治理」。
2. 指**排序前后对照**：开启新鲜度是 `D2 → D4 → D3 → D1 → D6`，仅关衰减恢复 `D1 → D2 → D3 → D4 → D6`。说明新文档反超旧文档靠的是可复算公式，不是拍脑袋。
3. 指**逐文档新鲜度表**：`D5` 未来生效被排除（标「未生效」而非「过期」）、`D6` 已过期按 demote 降权但仍在表里留痕。强调「适用性门控不受开关影响」。
4. 把「过期处置」从 `demote` 改成 `exclude` 再算一次 → `D6` 从列表消失；说明三档处置的差别与「降权 ≠ 已隔离」——demote 下过期文档仍参与 claim 抽取，正是被冲突检测抓出来的。
5. 指**冲突与裁决**：婚假 `10 天` vs `15 天` → `trust_newer_with_review / 需复核`；报销上限 `5000 元` vs `8000 元` → `trust_higher_authority`。再看负向对照：GB 地区不算冲突、接口超时同值不算冲突。最后展开 `resolution_log`，证明被淘汰的断言留痕而非删除。

## 4. 「类似好功能」的研究结论

`docs/knowledge/02-candidates.md` 按「与本项目契合度 / 面试考察热度 / 实现成本」三维度评估了 14 个候选，**Top5 推荐纳入本期**：

1. **答案缓存的版本感知失效**——与新鲜度共享 `revision` / `valid_from`，成本最低；
2. **逐句 grounding 与 claim 级引用**——EvidenceRecord 已把 claim 与支持片段绑好，是天然下一层；
3. **近重复与文档去重**——内容指纹已有 `checksum` 基础，能减少重复副本干扰裁决；
4. **检索可解释性（分数拆解）**——现有 `search_debug` 已有骨架，加新鲜度/权威度分量即可；
5. **金标 / 金丝雀回归集**——把「证据重排不翻转结论」「重复副本不改变结果」变成可复跑用例。

**明确不做**（保持「未做」标注，不夸大）：真实压测与容灾、监控告警 SLO、SSO/OIDC、真实账单校准、屏幕阅读器实测、质量基线冻结、NLI 模型级矛盾识别、权威注册表审批流、真实 CDC 近实时增量、跨缓存失效链路、真实腾讯云上线。

调研来源：20 条可核实 URL 与中文面试原题，检索日期 2026-11-14，见 `docs/knowledge/01-research.md` §7。所有外部经验阈值都标注「非本项目实测」。
