## 一、原理：图片型文档到底难在哪

### 1.1 六种典型情况，不能一概而论

「图片型文档」不是一类东西，而是六种诉求完全不同的东西。把它们混成一句「上多模态大模型」是典型的设计偷懒。

| 类型 | 页内特征 | 有无文字层 | 解析诉求 | 三级链路落点 | 三态 |
| --- | --- | --- | --- | --- | --- |
| 扫描页 | 整页是位图，文字被「拍」进去 | 无 | 把像素里的字还原成可检索文本 | P0 探测 → P1 收费 OCR | `【占位】`（P1 契约 `__TBC__`、未接通） |
| 截图 | 界面 / 代码 / 聊天记录，文字清晰但嵌在位图里 | 无（或仅零散） | OCR + 版面块划分 | P1 | `【占位】` |
| 图表 / 流程图 | 柱、折线、框线、箭头，语义在结构里 | 无 | 趋势、关系的语义描述，坐标读数 | P2 已接通，可做语义描述；精确读数仍以可回溯原文为准 | `【已落地】`（端点 + 连通性） |
| 带文字的照片 | 拍下来的合同、白板、招牌，常带透视畸变 | 无 | OCR + 几何校正 | P1 | `【占位】` |
| 纯装饰图 | logo、页眉、背景、分隔线 | 无意义 | **应当丢弃，不进分块** | P0 空白 / 纯色 / 小图过滤 | `【占位】`（骨架） |
| 公式图 | 数学公式被转成图片 | 无 | 还原成 LaTeX / 结构化表达 | 当前链路仍无法可靠还原 | `【未接通】` |

关键结论：**装饰图不该被「理解」，它该被识别出来然后丢掉**；扫描页需要的是 OCR，不是视觉问答；真正需要语义理解的主要是图表 / 流程图。P2 已接通并跑通双图连通性，但**这不等于图表语义理解已有质量基线**——精确读数仍须回溯，见 2.4。

### 1.2 「有没有文字层」不能只看扩展名

扩展名只说明**容器**，不说明页内是矢量文字还是位图。这是图片解析最容易踩的坑：

- 一个 `.pdf` 里可以混排：封面是位图、正文有文字层、附录是截图。判据必须**逐页、逐块（block）**地下，而不是逐文件地下。
- PDF 内部对象分两类：带 `/Font` 的文本绘制指令，和 `/Image` 这类图像 XObject。看到后缀是 PDF 不能推出「有文字层」。
- 文字层「存在」不等于「可用」：扫描件被 OCR 后把文字塞回 PDF，会产生隐藏层、透明层、错乱的坐标映射或字体编码，抽出来可能是乱码或空串。
- 图片容器也各有门道：JPEG / PNG / TIFF 的编码不同，PNG 可能有透明通道，TIFF 可能多页，EXIF 可能带方向（Orientation）——先把容器读对，才谈得上后续。
- 反之，`.png` 里若嵌了矢量文字（少见但可能），也不能仅凭后缀断言「一定是位图」。

因此判据应当是「**每页的文本抽取结果 + 图像对象占比 + 图像结构信号**」的组合，示意如下（伪代码，非项目源码）：

```python
# 伪代码：逐页探测，返回结构化信号，不据扩展名下结论
def probe_page(page):
    return {
        "has_text_layer":     bool,   # 中文说明：是否检测到文本绘制对象
        "text_char_count":    int,    # 中文说明：可抽取字符数（乱码/空串会很低）
        "image_object_count": int,    # 中文说明：页内图像对象数
        "image_area_ratio":   float,  # 中文说明：图像面积占整页比例
        "page_index":         int,    # 中文说明：页码，用于回溯
    }

# 判定逻辑示意：文字层缺失且图像占比高 => 疑似扫描页，建议交 P1 OCR
needs_ocr = (not page.has_text_layer) and (page.image_area_ratio > T_IMAGE)  # T_IMAGE：阈值，演示默认，待真实语料校准
```

`probe_page` 这类探测函数与 backend 既有的 `parse_range` / `PageText` / `ParsedDoc` 承载点是配套关系 `【已落地】`；而「把探测结果送进质量门禁、进而触发升级」的整体骨架属于 `【占位】`（#31 范畴）。

### 1.3 三级链路里图片问题的分工

主理人已定的架构是**三级解析**，图片问题被拆到不同层，而不是压给一个模型：

| 级别 | 名称 | 对图片做什么 | 依赖 | 三态 |
| --- | --- | --- | --- | --- |
| P0 | 自研 `local` | 探测容器、读元数据、判空白/纯色、产出**结构化信号** | 纯标准库，可选 `pypdf` + `Pillow` | `【占位】`（骨架，#31） |
| P1 | 收费 OCR API | 把像素里的文字变成结构化文本 | 外部 API，契约 `__TBC__` | `【占位】`（仍未接通） |
| P2 | 多模态 LLM 兜底 | 在确需语义理解时（图表/流程图）兜底 | `DISCOVERY_BASE_URL` / `DISCOVERY_API_KEY` / `DISCOVERY_MODEL` 注入的 OpenAI 兼容端点；`PARSING_VISION_*` 可覆盖 | `【已落地·已接通并实测】` |

一句话：**P0 负责「看得出这是什么情况」，P1 负责「把字取出来」，P2 负责「实在需要理解时兜底」**。P2 是最后一道、最贵的一道，不是默认的一道：虽已接通，仍受质量门禁与 90:10 预算闸门约束（见 05 篇），正常文档 0% 升级。

### 2.2 P0 结构化降级：离线 / 调用失败时的兜底

`structured_fallback()`（中文说明：结构化降级函数）现在的定位是 **`PARSING_OFFLINE=1` 一键全离线、或 P2 调用失败时的兜底**，**不再是默认路径**；默认路径是 P2 已接通的真实视觉链路（受质量门禁与 90:10 预算闸门约束）。兜底路径只做**确定性的、可单测的**统计，**只输出可测事实**（容器、尺寸、是否空白、是否建议送 OCR），**不描述图片内容、不编造文字或数字**——这是它不会变成幻觉源的原因。

兜底路径设计上能输出的确定性信号 `【已落地·兜底路径】`：

| 能力 | 具体做什么 | 产出信号（英文键名 / 中文说明） |
| --- | --- | --- |
| 容器与编码识别 | 读 magic bytes / 头信息（PNG `IHDR`、JPEG `SOI/APP`、`%PDF-`、TIFF），不靠扩展名 | `container` 容器类型、`encoding` 编码 |
| 尺寸 / DPI / 色彩模式 / EXIF | 宽高、DPI、色彩模式（`RGB`/`L`/`CMYK`/`1`）、EXIF 方向、是否含 ICC | `width` 宽、`height` 高、`dpi` 分辨率、`color_mode` 色彩模式、`exif_orientation` 方向 |
| 是否二值 / 纯色 / 空白页 | 颜色直方图、唯一色数、方差与极差、非白像素占比 | `blank_page` 空白页、`near_mono` 近二值、`solid_color` 纯色 |
| 像素级简单特征 | 边缘密度近似、粗略连通块计数、横竖线投影（判断像表格/框线）、宽高比、图像占页比 | `edge_density` 边缘密度、`line_projection` 线投影、`aspect_ratio` 宽高比 |
| 序列化为文本供受限推断 | 把上述信号序列化成结构文本，喂给纯文本 LLM 做**受限**判断 | `image_signals` 图像结构信号（文本） |

把这些信号序列化，形态大致如下（示意 JSON，非真实接口）：

```json
{
  "doc_id": "文档标识",
  "page_no": 7,
  "container": "png",                  // 中文说明：容器类型
  "width": 1654,                        // 中文说明：像素宽（示意值，非实测结论）
  "height": 2339,                       // 中文说明：像素高
  "color_mode": "L",                   // 中文说明：灰度模式
  "image_area_ratio": 0.93,            // 中文说明：图像占整页比例
  "text_char_count": 0,                // 中文说明：可抽取字符数
  "blank_page": false,                 // 中文说明：是否空白页
  "near_mono": true,                   // 中文说明：是否近二值（常见于扫描/线稿）
  "edge_density": "high",              // 中文说明：边缘密度分档（定性，非实测）
  "line_projection": "table_like"      // 中文说明：横竖线投影呈表格状
}
```

兜底路径下，提示词只允许做**受限推断**（判断类型、决定去向），不允许「看图说话」、不允许输出数字：

```text
# 受限推断提示词骨架：仅在兜底路径使用，示意、非真实调用
输入：下面是某页的图像结构信号（纯统计量，不是图像本身）。
请只回答三个受限选项之一，不要描述图中内容、不要猜测文字、不要输出数字：
  A. 疑似扫描页 -> 建议送 OCR
  B. 疑似空白/装饰图 -> 建议丢弃
  C. 信息不足 -> 建议保留 P0 结构化降级结果并标记低置信度
信号：{image_signals}
```

> **边界（改写后）**：以上是**离线 / 调用失败时的结构化兜底**，**不是**视觉理解的默认替代。
> 仅在兜底路径下，纯文本模型不接收像素、只读一串结构化统计量做受限分类；而**默认路径下 P2 已接通并真实接收像素**（见 2.3 实测）。
> 谁能把「兜底只输出可测事实、不编造内容」讲清楚，谁就把「降级」讲成了工程判断，而不是一句「我们没接模型」。

### 2.3 P2 已接通：请求构造、双图实测与参数校准

**端点配置** `【已落地】`：默认回退 `DISCOVERY_BASE_URL`（中文说明：发现网关基址，值由环境变量注入，**不写具体 URL**）+ `DISCOVERY_API_KEY`（中文说明：鉴权密钥，值由环境变量注入，**不写具体值**）+ `DISCOVERY_MODEL`（中文说明：默认视觉模型，值为 `deepseek-v4.1-flash-1017`）；可由 `PARSING_VISION_*`（中文说明：解析视觉链路专用覆盖配置族，具体字段 `__TBC__`）覆盖；`PARSING_OFFLINE=1` 一键全离线走 2.2 兜底；调用失败由 `structured_fallback()` 兜底并留痕。

**实测 2 · 双图对照传图**（`temperature=0`、`max_tokens=256`，单次功能连通性实测，非压测）：

| 图 | 图内容（受控合成） | 模型回答 | 单次耗时 | `prompt / completion / total` tokens（中文说明：输入 / 输出 / 合计 token 数） |
| --- | --- | --- | --- | --- |
| A | 浅蓝底 / 深蓝字 `73492` / 标签 `CODE-A` | `73492 on a light blue background with the label 'CODE-A' below.` | 1406 ms | 267 / 90 / 357 |
| B | 浅黄底 / 红字 `18620` / 标签 `CODE-B` | `The image shows the number 18620 in dark red on a pale yellow background, with the label 'CODE-B' below it.` | 2463 ms | 267 / 166 / 433 |

> **判定边界**：这是单次双图连通性实测，**不是质量基线**；未做真实语料集评测、未做压测、未做 P1 接入；不据此推断准确率 / P95 / 吞吐；`prompt_tokens`（中文说明：输入 token 数）实测 267 是单次记录，不是成本基线。

**实测 3 · 推理开关**（同题固定 `temperature=0`，单次实测）：

| 配置 | 单次耗时 | `reasoning_tokens`（中文说明：推理 token 数） | 结论 |
| --- | --- | --- | --- |
| 基线 | 979 ms | 55 | — |
| `thinking:{"type":"disabled"}` | 467 ms | 0 | **生效** |
| `reasoning:false` | 3413 ms | 55 | 无效 |
| `reasoning:true` | 945 ms | 55 | 无效 |

> 结论：元数据里 `output_modalities[0].supported_parameters.reasoning` 这个布尔参数**不生效**；项目既有的 `thinking` 字段才是对的，低思考档用它。这属于「照元数据臆断参数行为」被实测纠正的第二个例子。

要点与约束：

- **多图与文本混排**：`messages[].content` 是数组，可放多个 `image_url` 与一个 `text`；数组顺序要与「第几页 / 第几区域」一一对应，便于结果回溯。
- **data URI 传图**：实测 1 的 `sources.values = ["url","base64"]` 表明 URL 与 base64 两种来源都支持；`data:<mime>;base64,<数据>` 内联避免额外托管。体积、分辨率档位（`detail` 之类）、单页图数上限仍 `__TBC__`，**不推断填写**。
- **token / 分辨率 / 成本约束**：`max_tokens` 元数据上限 1048576，实测仅取 256；`prompt_tokens` 单次实测 267；分辨率与图数直接影响 token，价格仍 `__TBC__`，因此升级必须由 90:10 预算闸门（见 05 篇）控制。
- **超时与重试**：只对可重试错误（网络抖动、限流）做有限重试，配合请求指纹去重避免重复计费；具体超时、次数、错误码 `__TBC__`。
- **当前实际会发生什么**：默认路径**真实发出请求并返回视觉结果**；只有 `PARSING_OFFLINE=1`、端点不可达、模型不支持、被预算拦截或调用失败时，才走 `structured_fallback()` 兜底并打降级标记。

降级标记（**仅在离线 / 失败 / 被拦时产生，不再是常态**）：

| 标记（英文键名） | 中文说明 | 触发条件 |
| --- | --- | --- |
| `vision_unavailable` | 离线开关开启 / 视觉端点不可达 | `PARSING_OFFLINE=1`、连接失败 |
| `vision_unsupported` | 所选模型不支持传图 | 选中 4 个纯文本模型、不接受 `image_url` |
| `vision_budget_exceeded` | 视觉链路预算被拦 | 见 05 篇 90:10 预算闸门 |
| `vision_timeout` | 视觉调用超时 | 超过 `__TBC__` 时限 |
| `vision_rate_limited` | 视觉调用被限流 | 上游返回限流，错误码 `__TBC__` |

> 这些标记与 05 篇的 `escalation_budget_exceeded` 是**两层**：前者在 P2 适配器层，后者在升级决策层；两者可能同时出现，**都要留痕**，不能互相吞掉。

### 2.4 图片结果的置信度与幻觉边界（保留并强化）

四条铁律 `【占位·骨架】`，**不因 P2 接通而撤销任何一条**：

1. **图片里的精确文字 / 数字仍以 OCR 为准**。实测 2 证明模型**能**读出数字，但那是受控合成图的功能连通性证明；生产里关键数值仍以 OCR 的结构化输出并回溯原文为准。P1 收费 OCR 未接通时，宁可标「需人工复核 / 低置信度」，也不把视觉回答写进权威字段。
2. **禁止视觉模型复述关键数值**写入分块——金额、日期、条款号、百分比、坐标读数一律不来自视觉回答；让 LLM 从图里「读」数字再写进分块，是幻觉高发区。
3. **引用可回溯到页与区域**：每个来自图片的信号都要带定位信息，不能只留一句「模型说的」。
4. **分辨率与 token 成本约束**：`prompt_tokens` 单次实测 267、`max_tokens` 元数据上限 1048576，价格 `__TBC__`；用 90:10 预算闸门控制最贵链路占比。

> **不要反向夸大**：实测 2 是两张受控合成图，只证明「通道连通」；真实扫描件 / 复杂图表的数字幻觉风险**未经任何真实语料集评测覆盖**，因此「数字以 OCR 为准」这条铁律一条都不撤销。

允许 / 禁止的推断边界：

| 推断类型 | 是否允许 | 说明 |
| --- | --- | --- |
| 「这页像扫描件，建议送 OCR」 | 允许 | 兜底路径的受限分类，基于结构信号 |
| 「图里呈上升趋势」 | 允许（P2 已接通），标低置信度 | 语义判断，非精确读数；未做质量基线评测 |
| 「合同金额是 123,456 元」 | **禁止** | 必须来自 OCR 并回溯原文；禁止用视觉回答 |
| 「把流程图复述成步骤」 | 谨慎允许并标低置信度 | 易漏分支，需人工复核 |
| 「还原公式为 LaTeX」 | 当前禁止 | 链路不可靠还原，标 `【未接通】` |

回溯字段（复用既有承载点 `【已落地】`：`chunk_document` 已带 `confidence` / `source_level` / `block_type`）：

| 字段（英文键名） | 中文说明 |
| --- | --- |
| `doc_id` | 文档标识 |
| `page_no` | 页码 |
| `region` / `bbox` | 区域 / 坐标框（若 OCR 提供坐标则透传，否则 `__TBC__`） |
| `parser_level` | 结果来自哪一级（P0 / P1 / P2） |
| `source_level` | 既有来源层级字段，承载结果层级 |
| `confidence` | 该结果的置信度 |
| `degrade_reason` | 若走兜底 / 被拦，记录 `vision_unavailable` 等标记 |

> 图片链路产出的置信度**不与文本链路横向打分排序**（呼应 `NOT_COMPARABLE` 的精神，但不改动 `eval/` 冻结口径）。

## 四、诚实边界

- 已接通并实测的是**双图功能连通性**，**不是质量基线**；未做真实语料集评测、未做压测、未做 P1 收费 OCR 接入。
- **P1 收费 OCR 仍未接通**，契约字段保持 `__TBC__`；精确文字 / 数字的权威来源问题因此仍未彻底解决。
- 端点由 `DISCOVERY_BASE_URL` / `DISCOVERY_API_KEY` / `DISCOVERY_MODEL` 环境变量注入、`PARSING_VISION_*` 可覆盖；具体 URL / 鉴权值不写；价格 `__TBC__`；`prompt_tokens` 267、单次耗时 ms 等均为**单次实测记录**，不是压测 / P95 / 成本基线。
- `thinking` 字段生效、元数据布尔 `reasoning` 不生效（实测 3）；不据元数据臆断参数行为。
- 图片精确文字 / 数字以 OCR 为准，**禁止视觉模型复述关键数值**，引用回溯到页与区域；实测能读数字**不等于**生产可用。
- `structured_fallback()` 是离线 / 失败兜底，只输出可测事实、不编造内容；**不再是默认路径**。
- `eval/` 冻结对象的 `__TBC__` / `NOT_COMPARABLE` / `real_api` 阻断口径**不变、不绕过**；本篇三态图例与之相互独立，不改动、不绕过。
- 三级解析子系统整体是**骨架 + 演示切片**（#31 范畴），非上线交付；真实压测、监控告警与 SLO 未做；阈值（`T_IMAGE` 等）为演示默认 / 待真实语料校准。

> 小结：这次返工真正展示的是**实测纠偏**——从「没读 `input_modalities` 就下能力结论」到「补读元数据 + 双图实测后承认已接通」。但接通不等于可以夸大：功能连通性、质量基线、生产可用性是三件事。分级、确定性、可降级、可回溯、数字以 OCR 为准，仍是这篇的骨架。
