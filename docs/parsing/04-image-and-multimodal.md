## 一、原理：图片型文档到底难在哪

### 1.1 六种典型情况，不能一概而论

「图片型文档」不是一类东西，而是六种诉求完全不同的东西。把它们混成一句「上多模态大模型」是典型的设计偷懒。

| 类型 | 页内特征 | 有无文字层 | 解析诉求 | 三级链路落点 | 三态 |
| --- | --- | --- | --- | --- | --- |
| 扫描页 | 整页是位图，文字被「拍」进去 | 无 | 把像素里的字还原成可检索文本 | P0 探测 → P1 收费 OCR | `【占位】`（P1 契约 `__TBC__`） |
| 截图 | 界面 / 代码 / 聊天记录，文字清晰但嵌在位图里 | 无（或仅零散） | OCR + 版面块划分 | P1 | `【占位】` |
| 图表 / 流程图 | 柱、折线、框线、箭头，语义在结构里 | 无 | 趋势、关系的语义描述，坐标读数 | 只有 P2 才谈得上「理解」；P0 只给结构信号 | `【未接通】` |
| 带文字的照片 | 拍下来的合同、白板、招牌，常带透视畸变 | 无 | OCR + 几何校正 | P1 | `【占位】` |
| 纯装饰图 | logo、页眉、背景、分隔线 | 无意义 | **应当丢弃，不进分块** | P0 空白 / 纯色 / 小图过滤 | `【占位】`（骨架） |
| 公式图 | 数学公式被转成图片 | 无 | 还原成 LaTeX / 结构化表达 | 当前链路无法可靠还原 | `【未接通】` |

关键结论：**装饰图不该被「理解」，它该被识别出来然后丢掉**；扫描页需要的是 OCR，不是视觉问答；真正需要语义理解的只有图表 / 流程图这一类，而它恰恰是当前最没能力做的一类。

### 1.2 「有没有文字层」不能只看扩展名

扩展名只说明**容器**，不说明页内是矢量文字还是位图。这是图片解析最容易踩的坑：

- 一个 `.pdf` 里可以混排：封面是位图、正文有文字层、附录是截图。判据必须**逐页、逐块（block）**地下，而不是逐文件地下。
- PDF 内部对象分两类：带 `/Font` 的文本绘制指令，和 `/Image` 这类图像 XObject。看到后缀是 PDF 不能推出「有文字层」。
- 文字层「存在」不等于「可用」：扫描件被 OCR 后把文字塞回 PDF，会产生隐藏层、透明层、错乱的坐标映射或字体编码，抽出来可能是乱码或空串。
- 图片容器也各有门道：JPEG / PNG / TIFF 的编码不同，PNG 可能有透明通道，TIFF 可能多页，EXIF 可能带方向（Orientation）——先把容器读对，才谈得上后续。
- 反之，`.png` 里若嵌了矢量文字（少见但可能），也不能仅凭后缀断言「一定是位图」。

因此判据应当是「**每页的文本抽取结果 + 图像对象占比 + 图像结构信号**」的组合，示意如下（伪代码，非项目源码）：

```python
# 伪代码：逐页探测，返回结构化信号，不据扩展名下结论
def probe_page(page):
    return {
        "has_text_layer":     bool,   # 中文说明：是否检测到文本绘制对象
        "text_char_count":    int,    # 中文说明：可抽取字符数（乱码/空串会很低）
        "image_object_count": int,    # 中文说明：页内图像对象数
        "image_area_ratio":   float,  # 中文说明：图像面积占整页比例
        "page_index":         int,    # 中文说明：页码，用于回溯
    }

# 判定逻辑示意：文字层缺失且图像占比高 => 疑似扫描页，交给 P1 OCR
needs_ocr = (not page.has_text_layer) and (page.image_area_ratio > T_IMAGE)  # T_IMAGE：阈值，演示默认，待真实语料校准
```

`probe_page` 这类探测函数与 backend 既有的 `parse_range` / `PageText` / `ParsedDoc` 承载点是配套关系 `【已落地】`；而「把探测结果送进质量门禁、进而触发升级」的整体骨架属于 `【占位】`（#31 范畴）。

### 1.3 三级链路里图片问题的分工

主理人已定的架构是**三级解析**，图片问题被拆到不同层，而不是压给一个模型：

| 级别 | 名称 | 对图片做什么 | 依赖 | 三态 |
| --- | --- | --- | --- | --- |
| P0 | 自研 `local` | 探测容器、读元数据、判空白/纯色、产出**结构化信号** | 纯标准库，可选 `pypdf` + `Pillow` | `【占位】`（骨架，#31） |
| P1 | 收费 OCR API | 把像素里的文字变成结构化文本 | 外部 API，契约 `__TBC__` | `【占位】` |
| P2 | 多模态 LLM 兜底 | 在确需语义理解时（图表/流程图）兜底 | OpenAI 兼容 `image_url` 传图端点 | `【未接通】`（当前无端点） |

一句话：**P0 负责「看得出这是什么情况」，P1 负责「把字取出来」，P2 负责「实在需要理解时兜底」**。P2 是最后一道、最贵的一道，不是默认的一道。

### 2.2 P0：不依赖视觉模型时，到底能做什么（结构化降级）

没有视觉模型，不等于对图片束手无策。P0 用纯标准库（可选 `pypdf` + `Pillow`）能做一批**确定性的、可单测的**处理，技术深度是实打实的：

| 能力 | 具体做什么 | 产出信号（英文键名 / 中文说明） | 三态 |
| --- | --- | --- | --- |
| 容器与编码识别 | 读 magic bytes / 头信息（PNG `IHDR`、JPEG `SOI/APP`、`%PDF-`、TIFF），不靠扩展名 | `container` 容器类型、`encoding` 编码 | `【占位】`（骨架） |
| 尺寸 / DPI / 色彩模式 / EXIF | 宽高、DPI、色彩模式（`RGB`/`L`/`CMYK`/`1`）、EXIF 方向、是否含 ICC | `width` 宽、`height` 高、`dpi` 分辨率、`color_mode` 色彩模式、`exif_orientation` 方向 | `【占位】` |
| 是否二值 / 纯色 / 空白页 | 颜色直方图、唯一色数、方差与极差、非白像素占比 | `blank_page` 空白页、`near_mono` 近二值、`solid_color` 纯色 | `【占位】` |
| 像素级简单特征 | 边缘密度近似、粗略连通块计数、横竖线投影（判断像表格/框线）、宽高比、图像占页比 | `edge_density` 边缘密度、`line_projection` 线投影、`aspect_ratio` 宽高比 | `【占位】` |
| 序列化为文本供受限推断 | 把上述信号序列化成结构文本，喂给**纯文本** LLM 做**受限**判断 | `image_signals` 图像结构信号（文本） | `【占位】` |

把这些信号序列化，形态大致如下（示意 JSON，非真实接口）：

```json
{
  "doc_id": "文档标识",
  "page_no": 7,
  "container": "png",                  // 中文说明：容器类型
  "width": 1654,                        // 中文说明：像素宽（示意值，非实测结论）
  "height": 2339,                       // 中文说明：像素高
  "color_mode": "L",                   // 中文说明：灰度模式
  "image_area_ratio": 0.93,            // 中文说明：图像占整页比例
  "text_char_count": 0,                // 中文说明：可抽取字符数
  "blank_page": false,                 // 中文说明：是否空白页
  "near_mono": true,                   // 中文说明：是否近二值（常见于扫描/线稿）
  "edge_density": "high",              // 中文说明：边缘密度分档（定性，非实测）
  "line_projection": "table_like"      // 中文说明：横竖线投影呈表格状
}
```

把它交给纯文本模型时，提示词只允许做**受限推断**（判断类型、决定去向），不允许「看图说话」：

```text
# 受限推断提示词骨架（示意，非真实调用）
输入：下面是某页的图像结构信号（纯统计量，不是图像本身）。
请只回答三个受限选项之一，不要描述图中内容、不要猜测文字、不要输出数字：
  A. 疑似扫描页 -> 建议送 OCR
  B. 疑似空白/装饰图 -> 建议丢弃
  C. 信息不足 -> 建议保留 P0 结构化降级结果并标记低置信度
信号：{image_signals}
```

> **这是全文最重要的一句边界**：以上是**结构化降级（structured degradation）**，不是视觉理解。
> 纯文本模型**从未接收到任何像素**，它只是在读一串结构化统计量，做一道受限的分类题。
> 谁把这句话说成「我们用 LLM 理解了图片」，谁就在面试里埋了一颗雷。

### 2.3 P2：真有视觉模型时，请求怎么构造（契约 `__TBC__`）

即便当前没有端点，**请求构造代码依然可以写、可以单测**（验证序列化正确、多图顺序正确）。这是「适配器已就绪、接入点清晰」的工程价值。OpenAI 兼容的形态如下（**所有真实值 `__TBC__`**）：

```json
{
  "model": "__TBC__",                       // 中文说明：模型名，未配置
  "endpoint": "__TBC__",                    // 中文说明：接口地址，未配置
  "auth": "__TBC__",                        // 中文说明：鉴权方式，未配置
  "max_tokens": "__TBC__",                  // 中文说明：token 上限，未配置
  "messages": [
    {
      "role": "user",
      "content": [
        { "type": "text",
          "text": "这是第 7 页的区域 2 与第 8 页的区域 1；只描述趋势与关系，不要抄录数字。" },
        { "type": "image_url",
          "image_url": { "url": "data:image/png;base64,__TBC__" } },  // 中文说明：第 7 页区域 2 的 base64 data URI
        { "type": "image_url",
          "image_url": { "url": "data:image/jpeg;base64,__TBC__" } }   // 中文说明：第 8 页区域 1 的 base64 data URI
      ]
    }
  ]
}
```

要点与约束：

- **多图与文本混排**：`messages[].content` 是数组，可放多个 `image_url` 与一个 `text`；数组顺序要与「第几页 / 第几区域」一一对应，便于结果回溯。
- **data URI 传图**：`data:<mime>;base64,<数据>` 内联，避免额外托管；体积、分辨率档位（`detail` 之类）、单页图数上限、token 上限全部 `__TBC__`，**不推断填写**。
- **超时与重试**：只对可重试错误（网络抖动、限流）做有限重试，且必须配合请求指纹去重，避免重复计费；具体超时、次数、错误码 `__TBC__`。
- **当前实际会发生什么**：端点未配置 → 适配器直接返回降级标记，请求根本不发出；即便将来补了端点，也只在此处替换 `__TBC__` 值，不动上游决策逻辑。

降级标记（适配器层产生，全部 `【未接通】` 时命中）：

| 标记（英文键名） | 中文说明 | 触发条件 |
| --- | --- | --- |
| `vision_unavailable` | 视觉端点未配置 / 不可达 | 未配置、连接失败 |
| `vision_unsupported` | 模型不支持传图 | 模型不接受 `image_url` |
| `vision_budget_exceeded` | 视觉链路预算被拦 | 见 05 篇预算闸门 |
| `vision_timeout` | 视觉调用超时 | 超过 `__TBC__` 时限 |
| `vision_rate_limited` | 视觉调用被限流 | 上游返回限流，错误码 `__TBC__` |

> 这些标记与 05 篇的 `escalation_budget_exceeded` 是**两层**：前者在 P2 适配器层，后者在升级决策层；两者可能同时出现，**都要留痕**，不能互相吞掉。

### 2.4 图片结果的置信度与幻觉边界

三条铁律 `【占位·骨架】`：

1. **图片里的文字必须以 OCR（P1）为准**。视觉模型不用于抄录 / 复述文字。
2. **绝不让视觉模型复述数字**——金额、日期、条款号、百分比、坐标读数一律来自 OCR 的结构化输出并回溯原文；让 LLM 从图里「读」数字再写进分块，是幻觉的高发区。
3. **引用可回溯到页与区域**：每个来自图片的信号都要带定位信息，不能只留一句「模型说的」。

允许 / 禁止的推断边界：

| 推断类型 | 是否允许 | 说明 |
| --- | --- | --- |
| 「这页像扫描件，建议送 OCR」 | 允许 | 受限分类，基于结构信号 |
| 「图里呈上升趋势」 | 将来允许（P2 接通后） | 语义判断，非精确读数 |
| 「合同金额是 123,456 元」 | **禁止** | 必须来自 OCR，且回溯原文 |
| 「把流程图复述成步骤」 | 谨慎允许并标低置信度 | 易漏分支，需人工复核 |
| 「还原公式为 LaTeX」 | 当前禁止 | 链路不可靠还原，标 `【未接通】` |

回溯字段（复用既有承载点 `【已落地】`：`chunk_document` 已带 `confidence` / `source_level` / `block_type`）：

| 字段（英文键名） | 中文说明 |
| --- | --- |
| `doc_id` | 文档标识 |
| `page_no` | 页码 |
| `region` / `bbox` | 区域 / 坐标框（若 OCR 提供坐标则透传，否则 `__TBC__`） |
| `parser_level` | 结果来自哪一级（P0 / P1 / P2） |
| `source_level` | 既有来源层级字段，承载结果层级 |
| `confidence` | 该结果的置信度 |
| `degrade_reason` | 若降级，记录 `vision_unavailable` 等标记 |

> 图片链路产出的置信度**不与文本链路横向打分排序**（呼应 `NOT_COMPARABLE` 的精神，但不改动 `eval/` 冻结口径）。

## 三、面试怎么讲

**30 秒版**

> 「我们把解析分三级：P0 自研本地探测、P1 收费 OCR、P2 多模态兜底。图片型文档不是一类东西——扫描页要 OCR、装饰图要丢掉、图表才谈得上理解。实查网关里 10 个模型全是纯文本，没有视觉端点，所以 P2 我只做了适配器、传图请求构造和优雅降级留痕，没敢说跑通视觉理解。」

**2 分钟版**（按此顺序讲）

1. 先分类：六种图片情况，诉求不同，不能一句「上多模态」糊过去。
2. 再讲判据：「有没有文字层」不靠扩展名，逐页逐块探测文本抽取 + 图像占比。
3. 讲无视觉模型时的真功夫：容器/编码、尺寸/DPI/色彩/EXIF、空白/纯色/二值检测、像素简单特征、序列化成结构信号供纯文本 LLM 做**受限推断**。
4. 主动亮边界：「这是结构化降级，不是视觉理解，纯文本模型没收到过像素」。
5. 讲 P2 请求构造：`image_url` + base64 data URI、多图混排、顺序对应页与区域、降级标记；**当前无端点，只构造不发送**。
6. 收在幻觉边界：文字以 OCR 为准、不让模型复述数字、引用可回溯。

| 追问 | 应答要点 |
| --- | --- |
| 「你们用了多模态吗？」 | 没有可用端点，只做适配器 + 降级留痕；展示的是工程判断，不是跑通视觉。 |
| 「那图片里的字怎么办？」 | P1 OCR 为准，P0 只判「要不要送 OCR」。 |
| 「没有视觉模型你怎么处理图片？」 | 结构化降级：探测 + 序列化信号 + 受限推断，明确不是视觉理解（这是加分点，主动划清边界）。 |
| 「为什么不直接上视觉大模型？」 | 无端点、成本、尾延迟、数字幻觉风险、可控性差；分级更省更稳。 |
| 「怎么看有没有文字层？」 | 不靠后缀，逐页逐块探测文本抽取结果与图像对象占比。 |
| 「缺 API 是不是没做完？」 | 接入点清晰、契约 `__TBC__`、降级可观测；把「缺 API」讲成设计成熟度，而不是硬吹已跑通。 |

## 四、诚实边界

- **当前 10 个模型全为纯文本，网关无视觉 / 多模态端点**；嵌入与重排模型也无视觉能力。P2 不能跑通视觉理解，只能做适配器 + 请求构造 + 降级留痕。
- 真实外部 API 的接口地址、鉴权、请求/响应结构、配额、错误码、模型版本、价格一律 `__TBC__`，本篇未做任何推断填写。
- `eval/` 冻结对象的 `__TBC__` / `NOT_COMPARABLE` / `real_api` 阻断口径**不变**；本篇三态图例与之相互独立，不改动、不绕过。
- P0 的像素特征都是**统计量**，不是识别结果；「结构化降级」**不等于**「视觉理解」，纯文本模型从未接收像素。
- 图片中的文字必须以 OCR 为准，**禁止视觉模型复述数字**；引用需回溯到页与区域。
- 三级解析子系统整体是**骨架 + 演示切片**（#31 范畴），非上线交付；真实压测、监控告警与 SLO 未做。
- 本篇所有阈值（`T_IMAGE` 等）为演示默认 / 待校准，未写死结论；不写价格、不写 P95 / 吞吐 / 耗时实测数字。

> 小结：把「没有视觉模型」讲清楚，比假装「接了视觉大模型」更能体现工程判断。分级、确定性、可降级、可回溯，才是这篇真正要展示的东西。
