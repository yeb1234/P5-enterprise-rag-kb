## 0. 约定：术语与「三态」口径

### 0.1 三态声明（全文通用）

| 状态 | 含义 | 本文中的例子 |
| --- | --- | --- |
| **已实现** | 仓库里能读到、能跑的代码 | `block_type=table` 的规则判定、`parent_seq`（父块序号）字段 |
| **只设计** | 接口/结构/流程想清楚了，未落地为可运行实现 | 结构语义 JSON、七项稳定性检查、表格独立成块、坐标引用契约 |
| **未做** | 明确不做或条件不具备 | 工业级表格识别模型、跨页续表自动拼接、真实表格语料校准 |

> 把「只设计」讲成「已实现」，是演示里最容易被追问穿帮的地方。

### 0.2 术语首现表

| 术语 | 中文解释 |
| --- | --- |
| 结构语义（structural semantics） | 用「单元格 + 行列坐标 + 跨度 + 类型 + 单位」表达一张表，而不是用一段字符串 |
| 合并单元格（merged cell） | 一个值跨多行或多列；`rowspan`（跨行数）、`colspan`（跨列数）描述跨度 |
| 跨页表（table across pages / continued table） | 一张表在页边界断开，续页可能重复也可能不重复表头 |
| 无边框表 / 无线表（borderless table） | 靠空白对齐而非线条分列，列边界只能靠推断 |
| 嵌套表（nested table） | 单元格内部又是一张表，扁平结构无法表达 |
| 表头层级（multi-level header） | 多级表头，如「营收」下再分「Q1 / Q2」 |
| 包围盒（bbox，bounding box） | 表或单元格在页面上的坐标框，用于溯源与复核 |
| 线性化（linearization / flattening） | 把二维表拉平成一维文本行，行列绑定随之丢失 |
| 稀疏表示（sparse representation） | 被合并覆盖的格子不再单独出现，靠 `rowspan` / `colspan` 推导占位 |
| 覆盖矩阵（cell occupancy grid） | `n_rows × n_cols` 的网格，用来校验每个格子恰好被填一次 |
| 指纹（fingerprint） | 由首行、末行、列数、标题拼成的短标识，用于判断两页是否同一张表 |
| 置信度（confidence） | 解析结果可信程度的量化分，供检索降权与升级决策 |
| 父块回溯（parent chunk backtracking） | 命中子块后按 `parent_seq` 找回父块补上下文 |
| 引用（citation） | 回答中指向原文位置的定位信息，如页码 + 表 + 行列 |
| 规则级实现（rule-based） / 工业级表格识别（industrial-grade table recognition） | 前者靠手写规则（如数竖线），后者靠训练模型检测表格区域与结构 |

### 0.3 英文键名 / 字段名对照

`cells`（单元格集）、`row`（行号）、`col`（列号）、`rowspan`（跨行数）、`colspan`（跨列数）、`value`（值）、`type`（值类型）、`unit`（单位）、`header_levels`（表头层级数）、`header_rows`（表头行号）、`title`（表标题）、`caption_path`（章节路径）、`footnotes`（脚注）、`bbox`（包围盒）、`n_rows`（逻辑行数）、`n_cols`（逻辑列数）、`page_no`（页码）、`block_type`（块类型）、`parent_seq`（父块序号）、`seq`（块序号）、`content`（块内容）、`confidence`（置信度）、`source_level`（来源层级）、`table_id`（表标识）、`header_path`（表头路径）。

## 1. 表格为什么是 RAG（Retrieval-Augmented Generation，检索增强生成）里最容易坏的输入

### 1.1 七类失效模式

| 失效模式 | 机制 | 后果 |
| --- | --- | --- |
| 线性化后行列关系丢失 | 二维表被拉平成一维文本行 | 「1480」不知道属于哪一行、哪一列 |
| 合并单元格 | 一个值跨多行/多列，铺平后重复或缺失 | 表头与数据错位，多级表头无法还原 |
| 跨页表 | 表在页边界断开，续页常不重复表头 | 后半张表没有列名，检索命中即错答 |
| 无边框表 | 靠空白对齐分列而非线条 | 列边界靠猜，规则解析极易错列 |
| 嵌套表 | 单元格里又是一张表 | 扁平结构无法表达，或被当噪声丢弃 |
| 数字单位与表头错位 | 单位写在表头、千分位、百分号、货币符号 | 数值与单位脱钩，模型读出裸数或错单位 |
| LLM（Large Language Model，大语言模型）把表读成散文 | 生成式模型按语言先验补全 | 幻觉出不存在的关系、把行读成列 |

### 1.2 一个线性化的具体例子

```
华东  1250  1480  18.4%      ← 原表：事业部 | 营收(万元) Q1 | 营收(万元) Q2 | 同比(%)
华南   980  1020   4.1%
合计  2230  2500  12.1%
```

拉平后，「1480」丢掉了「华东 / 营收 / Q2 / 万元」四个约束。若提问「华东 Q2 营收是多少」，被检索到的这行文本里没有任何词能建立这个绑定，模型只能靠位置去猜 —— 而位置在多栏、跨页、有合并单元格时恰好最不可靠。**这不是模型不够聪明，是输入里已经没有这个信息了。**

### 1.3 本项目当前基线的失效点（已实现 / 未做）

`backend/app/services/parser.py:139` 的 `split_into_chunks()`：

```python
block_type = "table" if "|" in line and line.count("|") >= 2 else (...)
```

- 这是**已实现**的「规则级」判定：一行里有两个 `|` 就标成 `table`（块类型）。
- 但 `split_into_chunks()`（`parser.py:117`）把**每一行文本当成独立 unit**（`parser.py:141`），没有跨行聚合成表；表头与数据行被切进不同块，二维关系在分块这一步就丢了。
- 对无边框表、跨页表、合并单元格、嵌套表完全没有处理，属**未做**。
- 换句话说：`block_type=table` 这个标记目前只是「这行像表格」，不等于「这张表被结构化理解了」。这是 §5 要补的重点，也是「诚实边界」里必须承认的事实。

## 2. 「结构语义」的定义

### 2.1 从字符串到结构

「结构语义」指把表表示为 **`cells(row, col, rowspan, colspan, value, type, unit)`（单元格集：行号、列号、跨行数、跨列数、值、值类型、单位）**，再叠加 **表头层级 + 标题/脚注 + 坐标框**，而不是一段字符串。判据很简单：给一个 `(row, col)`，能否不靠猜就取回「值 + 单位 + 所属表头路径 + 在原文哪一页」。字符串做不到，结构可以。

### 2.2 字段字典

| 字段 | 中文 | 说明 |
| --- | --- | --- |
| `cells` | 单元格集 | 核心数组，稀疏表示，含表头与数据格 |
| `row` / `col` | 行号 / 列号 | 0 起始的**逻辑**坐标，不是像素位置 |
| `rowspan` / `colspan` | 跨行数 / 跨列数 | 合并单元格跨度，默认 1 |
| `value` | 值 | 数值用数字类型、文本用字符串，**不带单位** |
| `type` | 值类型 | `header`（表头）/ `row_label`（行标签）/ `number`（数值）/ `text`（文本）/ `empty`（空） |
| `unit` | 单位 | 从表头或脚注归一而来，与 `value` 分离 |
| `header_levels` / `header_rows` | 表头层级数 / 表头行号 | 多级表头的层数与所在行 |
| `title` / `caption_path` | 表标题 / 章节路径 | 供检索侧拼接上下文 |
| `footnotes` | 脚注 | 单位说明、统计口径、数据来源 |
| `bbox` | 包围盒 | 表在页面上的坐标框，用于溯源与复核 |
| `n_rows` / `n_cols` | 逻辑行数 / 列数 | 覆盖守恒校验的基准 |
| `confidence` / `source_level` | 置信度 / 来源层级 | 供检索降权与来源区分 |

### 2.3 一份可直接用的 JSON 结构示例

```json
{
  "table_id": "t-003",
  "title": "表 3  各事业部季度营收",
  "caption_path": "第三章 / 经营情况 / 营收明细",
  "page_no": 12,
  "bbox": [72, 96, 520, 336],
  "n_rows": 5, "n_cols": 4,
  "header_levels": 2, "header_rows": [0, 1],
  "cells": [
    {"row":0,"col":0,"rowspan":2,"colspan":1,"value":"事业部","type":"header","unit":null},
    {"row":0,"col":1,"rowspan":1,"colspan":2,"value":"营收","type":"header","unit":"万元"},
    {"row":0,"col":3,"rowspan":2,"colspan":1,"value":"同比","type":"header","unit":"%"},
    {"row":1,"col":1,"rowspan":1,"colspan":1,"value":"Q1","type":"header","unit":null},
    {"row":1,"col":2,"rowspan":1,"colspan":1,"value":"Q2","type":"header","unit":null},
    {"row":2,"col":0,"rowspan":1,"colspan":1,"value":"华东","type":"row_label","unit":null},
    {"row":2,"col":1,"rowspan":1,"colspan":1,"value":1250,"type":"number","unit":"万元"},
    {"row":2,"col":2,"rowspan":1,"colspan":1,"value":1480,"type":"number","unit":"万元"},
    {"row":2,"col":3,"rowspan":1,"colspan":1,"value":18.4,"type":"number","unit":"%"},
    {"row":3,"col":0,"rowspan":1,"colspan":1,"value":"华南","type":"row_label","unit":null},
    {"row":3,"col":1,"rowspan":1,"colspan":1,"value":980,"type":"number","unit":"万元"},
    {"row":3,"col":2,"rowspan":1,"colspan":1,"value":1020,"type":"number","unit":"万元"},
    {"row":3,"col":3,"rowspan":1,"colspan":1,"value":4.1,"type":"number","unit":"%"},
    {"row":4,"col":0,"rowspan":1,"colspan":1,"value":"合计","type":"row_label","unit":null},
    {"row":4,"col":1,"rowspan":1,"colspan":1,"value":2230,"type":"number","unit":"万元"},
    {"row":4,"col":2,"rowspan":1,"colspan":1,"value":2500,"type":"number","unit":"万元"},
    {"row":4,"col":3,"rowspan":1,"colspan":1,"value":12.1,"type":"number","unit":"%"}
  ],
  "footnotes": [{"marker": "*", "text": "数据未经审计；金额单位为万元"}],
  "confidence": 0.86,
  "source_level": "layout_parse"
}
```

示例自洽点：`value` 用数字 `1480` 而非字符串 `"1,480"`，单位单独放 `unit`（单位），正好解决 §1.1 的「数字单位错位」；`事业部` 与 `同比` 用 `rowspan=2`（跨行数）、`营收` 用 `colspan=2`（跨列数）表达合并单元格；`confidence`（置信度）如实写 `0.86` 而不是伪装成满分。

### 2.4 稀疏占位与坐标框为什么必须留

被合并覆盖的格子**不再单独出现**在 `cells` 里（示例中 `(1,0)`、`(1,3)` 被表头跨行覆盖，`(0,2)` 被 `营收` 跨列覆盖）。校验办法是重建一张 `n_rows × n_cols` 的覆盖矩阵：每个 cell 按 `rowspan × colspan` 填进去，要求**无空洞、无重叠** —— 这正是 §4.1 的单元格数守恒。本例 `Σ(rowspan×colspan) = 2+2+2+1+1+12 = 20 = 5×4`，恰好守恒。

`bbox`（包围盒）则让每个值能回指原页位置，回答时可以给「第 12 页表 3 第 2 行第 2 列」这样的引用；没有坐标，「可溯源」在演示里就讲不出来。

## 3. 常见表示与还原路径对比

### 3.1 能力矩阵

| 表示 | 合并单元格 | 跨页表 | 其他失效点 |
| --- | --- | --- | --- |
| HTML `<table>` | `rowspan` / `colspan` 原生支持 | 无跨页概念，需外部拼接 | 样式与语义混杂、不带坐标、解析宏容易出错 |
| LaTeX | `multirow` / `multicolumn` 可表达 | 需 `longtable` 类宏包，拼接仍在外部 | 依赖编译，还原成结构要解析宏 |
| Markdown 管道表 | **不支持** | **不支持**，每页独立成表 | 单元格内换行、`|` 转义困难，多级表头无解 |
| CSV | **不支持**，只能铺平 | 无表头重复语义 | 无类型 / 单位 / 跨度，数字与单位必然分离 |
| 坐标网格（`bbox` + 行列索引 + span） | 靠 span 字段可表达 | 靠指纹拼接 | 最接近结构语义，但依赖检测准确性 |

### 3.2 逐项失效点小结

Markdown 与 CSV 只适合**展示**，不适合做**结构化中间表示**：一旦写进去，`rowspan`、`unit`（单位）、表头层级就永久丢失。HTML 能保合并单元格但保不住跨页与坐标；LaTeX 表达力够，代价是要解析宏与编译环境。坐标网格是唯一能把「值、跨度、单位、位置」同时带上的表示，也是本文 §2 选择它的原因。

### 3.3 还原路径与降级顺序

```
PDF / 图片 → 表格区域检测 → 行列线或文本框聚类 → 结构推断（span、表头层级）
          → 序列化为坐标网格（§2 的 JSON）→ 按需降级导出 Markdown / CSV 供 LLM 消费
```

降级顺序：**坐标网格（保真）> HTML（保合并）> Markdown（保可读）> CSV / 纯文本（保命）**。
**降级只能单向**：结构一旦摊平成字符串就再也补不回 `rowspan`（跨行数）与 `unit`（单位）。所以结构语义必须在**入库前**定下来，不能指望问答时再还原 —— 这是整篇最该记住的一句。

## 4. 稳定性的工程做法（可量化检查项）

### 4.0 检查流水线

```
候选结构 JSON → ① 单元格数守恒 → ② 行列索引连续性 → ③ 表头重复检测
             → ④ 跨页拼接指纹 → ⑤ 数值类型一致性 → ⑥ 单位归一
             → ⑦ 置信度打分 → 通过则入库 / 不通过则降级或升级
```

### 4.1 七项检查总表（检查什么 / 失败信号 / 处置）

| # | 检查项 | 检查什么 | 失败信号 | 处置 |
| --- | --- | --- | --- | --- |
| 1 | 单元格数守恒 | 重建覆盖矩阵，`Σ(rowspan×colspan)` 是否等于 `n_rows×n_cols`，且无空洞 / 无重叠 | 有空洞，或同一格被两个 cell 声明 | 标可疑，回退到原检测框重推断；**不静默补 0**，降级为逐行文本并提示复核 |
| 2 | 行列索引连续性 | `row` / `col` 从 0 起连续、无越界 | 跳号、负索引、`col >= n_cols` | 重排或丢弃该结构，保留原始文本块 |
| 3 | 表头重复检测 | 相邻页 / 相邻表首行与前一表表头的文本相似度 | 续页被当成新表且丢表头 | 继承表头路径，并入同一 `table_id`（表标识） |
| 4 | 跨页拼接指纹 | 「首行 + 末行 + 列数 + 表标题」四元组是否一致 | 列数不一致却强行拼接 | 列数不符不拼，另起新表并告警 |
| 5 | 数值类型一致性 | 同一数据列 `type=number` 占比、`value` 能否解析为数值 | 数字列混入文本（表头错位、OCR 把 `1,250` 读成 `l,25O`） | 整列重识别或标低置信，禁止该列参与数值问答 |
| 6 | 单位归一 | `unit` 是否来自表头 / 脚注且全表一致 | 同列出现「万元」「元」混用 | 统一换算并在 `content`（块内容）里显式带单位，**禁止裸数字入库** |
| 7 | 置信度打分与升级 | 检测置信 + 结构校验通过率 + 数值一致性的合成分 | 合成分低于阈值 | 升级到更强解析路径或人工复核，并在 `confidence`（置信度）里如实记录 |

### 4.2 每项的可量化判据

1. **守恒**：`sum(c.rowspan * c.colspan for c in cells) == n_rows * n_cols`，且逐格填矩阵时重复填充即判重叠。
2. **连续性**：`set(rows) == set(range(n_rows))`，且 `max(col) < n_cols`。
3. **表头重复**：归一化（去空白、统一全半角）后文本相似度 `>= 0.9`（**经验起始值，需校准**）判为同一表头。
4. **指纹**：`(norm(first_row), norm(last_row), n_cols, norm(title))` 四元组相等才允许拼接；跨页另查前页末行与当前页首行的数据连续性。
5. **数值一致**：数字列 `number_ratio >= 0.9`（**经验起始值，需校准**）且 `value` 可被解析为数值。
6. **单位归一**：全表 `unit` 取值集合大小 `<= 1`，否则按换算表统一到同一单位。
7. **置信度**：低于阈值**不伪装成 `1.0`**，这是与当前骨架 `confidence=1.0`（`parser.py:50`）最关键的区别。

### 4.3 置信度合成与升级（示意，非标定）

```python
score = 0.4 * detect_conf + 0.3 * structural_pass_rate \
      + 0.2 * numeric_consistency + 0.1 * header_match
```

> 权重、阈值均为**经验起始值 / 示意**，未经真实语料校准，不是实测结论。

| 合成分（起始值） | 判定 | 处置 |
| --- | --- | --- |
| `>= 0.85` | 可用 | 直接入库，`block_type=table`（块类型标为表格） |
| `0.60 ~ 0.85` | 可疑 | 保留结构但下调 `confidence`（置信度），检索侧降权 |
| `< 0.60` | 不可信 | 不写结构化表，降级为逐行文本 + 打标记待人工 / 更强解析器复核 |

> 「升级」指换更强的解析路径（如版面解析服务，见本系列 PDF/OCR 专题），不是把同一个错结果再跑一遍。

## 5. 检索与问答侧怎么消费结构语义

### 5.1 表格块独立成 chunk（chunk，检索块）

一张表（或跨页合并后的整表）单独成一个 chunk，`block_type`（块类型）标 `table`，不与普通段落混切，切分窗口不得从表格中间断开。当前 `split_into_chunks()` 已有 `block_type` 字段与 table 判定（`parser.py:139`），但**按行切、未聚表**（§1.3）—— 独立成块属**只设计**。

### 5.2 保留表头上下文

序列化 `content`（块内容）时把「表标题 + 表头路径 + 行标签」拼进每个数据行，让单块自带语义：

```
表3 各事业部季度营收 | 营收(万元)/Q2 | 华东 = 1480 万元；同比(%) = 18.4%
```

这样即使块被单独检索到，`华东 / Q2 / 营收 / 万元` 四个约束都在，不必回溯整表。这正是 §1.2 那个「猜不出来」问题的正面解法。

### 5.3 父块回溯

`ChunkSpec.parent_seq`（父块序号）（`parser.py:49`）在实现里是 `parent_seq=(seq // 4) * 4`（`parser.py:163`），并在 `ingest.py:298` 写进分块 payload；命中子块后可按 `parent_seq` 回溯补上下文。这是**已实现**的字段，但当前是「每 4 个小块归一个父块」的简化规则，**不是按表格边界分组** —— 把父块边界对齐到 `table_id`（表标识）属**只设计**。

### 5.4 回答时给「行 / 列坐标」引用，而不是复述整表

```json
{"citation": {"doc_id": "d-001", "page_no": 12, "table_id": "t-003",
              "row": 2, "col": 2, "header_path": "营收(万元)/Q2",
              "value": 1480, "unit": "万元", "bbox": [72, 210, 160, 228]}}
```

好处：答案可复核（用户按页码 + 行列回原文核对）、可审计、不会因为复述整表引入新的抄写错误；`confidence`（置信度）低的引用可显式标注「解析置信度较低，建议核对原表」。

## 6. 四段式收尾：原理 → 本项目怎么落 → 面试怎么讲 → 诚实边界

### 6.1 原理

表格是二维结构，而 RAG 的分块与向量化默认按一维文本处理；一旦把表线性化（linearization），行列绑定、合并跨度、单位口径就永久丢失。解法是入库前就把表表示成 `cells(row, col, rowspan, colspan, value, type, unit)` + 表头层级 + 标题 / 脚注 + 坐标框，并用守恒、连续性、指纹、类型、单位、置信度六类检查守住结构；检索时整表独立成块、表头随行注入，回答时给行列坐标引用（citation）而不是复述整表。

### 6.2 本项目怎么落（三态对齐）

**已实现**：`block_type=table` 的规则判定（`parser.py:139`）、`parent_seq`（父块序号）回溯字段（`parser.py:49,163`、`ingest.py:298`）—— 字段位和最简单的规则有了。
**只设计**：§2 的结构语义 JSON、§4 的七项检查、§5 的独立成块 / 表头注入 / 坐标引用 —— 契约与检查项想清楚了，仓库里没有对应实现。
**未做**：工业级表格识别、跨页续表自动拼接、真实表格语料上的阈值校准、收费解析服务接入。
一句话：**「表格是个特殊块」这件事已经被骨架承认了，「表格是一张二维结构」这件事还停留在契约层。**

### 6.3 面试怎么讲（2–3 句）

「表格是二维结构，最容易被一维分块毁掉 —— 我不会把它摊成字符串，而是入库前就存成带 `rowspan` / `colspan`（跨行数 / 跨列数）、`unit`（单位）、表头层级和 `bbox`（包围盒）的单元格结构，并用覆盖矩阵守恒、跨页指纹、数值列一致性这些可量化检查决定它可不可信。检索时整表独立成块、把表头路径拼进每一行，回答只给『第 12 页表 3 第 2 行 Q2』这样的坐标引用，而不是把整张表复述一遍。」

### 6.4 诚实边界

1. **本项目的表格解析器是规则级自研实现，不等于工业级表格识别**：当前只有「一行里 `|` 数量 >= 2」这一条规则（`parser.py:139`），不检测表格区域、不推断合并单元格、不处理跨页续表、不识别无边框表与嵌套表。
2. §2 的结构语义 JSON、§4 的七项检查、§5 的独立成块与坐标引用**全部是只设计**，仓库里没有对应实现，也没有跑过任何真实表格语料。
3. §4 的阈值与权重是**经验起始值 / 示意**，未经校准，不是实测结论；§3 提到的 HTML / LaTeX / 坐标网格是**业界常见表示**，不代表本项目已支持。
4. 当前 `parent_seq` 是「每 4 块归一个父块」的简化规则（`parser.py:163`），不是按表格边界分组。
5. 表格识别质量依赖上游 OCR / 版面解析（见本系列 PDF/OCR 专题）；**P1 收费解析服务当前未接通**、凭证未提供，但 **P2 多模态兜底已接通**（实测见 PDF/OCR 专题 §6.2.1）—— 复杂无边框 / 跨页表可升级到已接通的 P2 多模态层，不过**当前只做规则级 P0，未做表格识别质量评测**，且该升级路径尚未接入表格链路。
6. 引用行号以当前骨架版本为准，后续重构需同步更新。
