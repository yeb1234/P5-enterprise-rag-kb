## 2. 分层架构

```
┌────────────────────────────────────────────────────────────────┐
│  前端「解析实验室」                                             │
│  策略下拉 auto / local_only / ocr_api / multimodal / off         │
│  逐页轨迹表：级别·置信度·耗时·升级自·预算拦截·原因·降级          │
└──────────────────────────┬─────────────────────────────────────┘
                           │ HTTP（/api/parse/*）
┌──────────────────────────▼─────────────────────────────────────┐
│  适配层  webapp/routers_parse.py  /  parsing/server.py（Docker） │
│  只做 HTTP ↔ 纯函数包转换，不写业务逻辑                        │
└──────────────────────────┬─────────────────────────────────────┘
                           │
┌──────────────────────────▼─────────────────────────────────────┐
│  ★ 路由层  parsing/router.py                                   │
│  split_pages → 质量门禁 needs_upgrade → VisionBudget            │
│  → 逐级调用策略 → ParseResult + ParseTrace                     │
└───────┬──────────────────┬──────────────────┬──────────────────┘
        │                  │                  │
┌───────▼──────┐  ┌────────▼────────┐  ┌─────▼────────────────┐
│ P0 local     │  │ P1 ocr_api      │  │ P2 multimodal        │
│ 纯标准库      │  │ 适配器          │  │ Discovery 视觉端点   │
│ + tables.py  │  │ 契约 __TBC__    │  │ image_url data URI   │
│ + images.py  │  │ available=False │  │ 双图实测已跑通       │
│ 已实现       │  │ 只设计          │  │ 已接通（失败才降级） │
└───────┬──────┘  └────────┬────────┘  └─────┬────────────────┘
        └──────────────────┴──────────────────┘
                           │
┌──────────────────────────▼─────────────────────────────────────┐
│  下游契约（不变）  backend/app/services/parser.py                │
│  ChunkSpec(page_no, section_path, block_type, confidence,        │
│            source_level, parent_seq) → chunks 表 / Milvus / 引用 │
└────────────────────────────────────────────────────────────────┘
```

**为什么把适配层和路由层分开**：`parsing/` 可以脱离 FastAPI 单独 `import`、单独跑单测、单独打镜像；`webapp/` 是 SQLite 演示替身，`backend/` 是生产骨架，两者都能接同一个纯函数包，不会互相拖累。

## 3. 一次解析发生了什么（逐页）

1. **分页**：纯文本按 3000 字符切，PDF 用 `pypdf.extract_text()` 逐页，图片整页。大文件不整块进内存。
2. **P0 自研**：解码 → `extract_tables()` 抽出结构化表 → 生成 `Block(paragraph/table/image)` → 计算 `QualitySignals`。
3. **质量门禁**：零字符 / 非文本来源且字符低于阈值 / 置信度 < 0.75 / 表格检查未全过 → 判「需要升级」，写 `reason`。
4. **P1**：`available()` 为 `False` 时跳过并记 note（`__TBC__` 契约未配置），不发起任何外部请求。
5. **预算闸门**：向 `VisionBudget` 申请 P2 名额；`slots = max(1, ceil(页数 × 0.10))`。
6. **P2**：有端点则构造 `image_url` + base64 data URI 发送；无端点走 `structured_fallback()`，输出**图片结构事实**并标 `vision_unavailable`。
7. **留痕**：`ParseTrace` 记录级别、置信度、耗时、从哪级升上来、是否被预算拦、`reason`、`notes`。
8. **保留正文**：任何降级都把本级已解析到的正文拼回去，不整页丢弃（`_merge_fallback()`）。

## 4. 我的设计取舍（比「固定 90:10 随机分流」好在哪）

用户原话是「兜底大概 80:20 还是 90:10 你自己定」。我定 90:10，但**改变了它的性质**：

| | 固定随机分流 | 本实现 |
|---|---|---|
| 触发依据 | 随机数 | 可复算的质量信号 |
| 正常文档 | 也有 10~20% 的页白调最贵链路 | **0% 触发** |
| 疑难页命中率 | 靠运气 | 由门禁确定性保证 |
| 超支行为 | 无 | 显式 `escalation_budget_exceeded` + 回退 |
| 面试可解释性 | 「拍脑袋定的」 | 「上限/熔断线，阈值需用真实语料校准」 |

另一个额外设计是**解析轨迹可视化**：把「为什么这一页升级」变成一张能指给人看的表。演示技术深度最怕只讲概念没有证据，轨迹表就是证据。

## 5. 现场演示 5 步（约 3 分钟）

1. 启动 `python -m uvicorn webapp.main:app --port 8765`，`admin / admin123` 登录，进「解析实验室」。
2. 指三级可用性卡：P0 可用、P2 已接通、P1 未接通；说明「网关 `/models` 的 `input_modalities` 显示 10 个模型里 6 个支持 image」，并强调这是**读元数据 + 双图对照实测**得来的，不是看模型名猜的。
3. 上传一份带 Markdown 表格的说明书 → 轨迹显示 `local / local_ok / 0 次升级`，预览里能看到 `[行2·列1]` 这样的结构语义坐标。
4. 上传一张 PNG → 轨迹显示 `multimodal / vision_applied / degraded=None`，预览是模型对图片内容的结构化描述，`upstream` 里能看到模型名与 token 用量；再设 `PARSING_OFFLINE=1` 跑同一张图，轨迹变成 `vision_skipped / 结构化降级`，讲清「关掉视觉时只输出可测事实，绝不编造内容」。
5. 切成 `off`、`local_only`、`multimodal` 各跑一次同一文件 → 轨迹差异并排，讲清开关、真实调用成本与预算闸门；再切回 `auto`。

可加问：「20 页全是无文本层会怎样？」→ 答：前 2 页拿到 P2 名额，第 3 页起标 `escalation_budget_exceeded` 并回退，不静默失败。

## 6. 面试三句话版本

> 我把「原始字节 → 结构化文本」抽成了可插拔策略层，下游 chunks 表和引用契约完全不动：自研规则层先跑并产出可复算的质量信号，只有判到无文本层、置信度不足或表格结构不自洽才逐级升级到收费 OCR 和多模态；最贵的一层有 10% 的页数熔断线，超了就显式留痕回退。多模态层已经接通并用双图对照实测跑通（不同数字、背景色、标签都精确命中），但我不会说成「具备生产级视觉质量」——那是功能连通性实测，不是质量基线；P1 收费 OCR 仍未接通，接口字段保持 `__TBC__`，`PARSING_OFFLINE=1` 可以一键全离线并展示诚实的降级路径。

## 6.1 实测记录（2026-11-14，用来回答「你怎么证明」）

| 项 | 方法与结果 |
|---|---|
| 网关能力 | 读 `/models` 的 `input_modalities`：10 个模型里 **6 个支持 `image`**，目标模型支持 `url` / `base64`；`python -m parsing.vision_probe` 可复跑 |
| 传图对照 | 图 A（浅蓝 `73492` / `CODE-A`）→ 精确回答，1406 ms；图 B（浅黄 `18620` / `CODE-B`）→ 精确回答，2463 ms；两次回答不同，排除「靠猜或复述提示词」 |
| 完整链路 | `ParseRouter.parse_document()` 上传同一张图 → `reason=vision_applied`、`degraded=None`、1403 ms，回答含 `73492` 与颜色判断 |
| 低思考档 | 同题固定 `temperature=0`：基线 979 ms / `reasoning_tokens=55`；`thinking={"type":"disabled"}` 467 ms / 0；`reasoning=false` 3413 ms / 55（无效）；`reasoning=true` 945 ms / 55（无效） |

**判定边界**：以上证明「能连通、能识别、字段生效」，不证明准确率、不证明成本可控、不证明 P1 可用；未做真实语料集评测与压测。

## 7. 诚实边界

- P0 表格是**规则级**结构还原，不是工业级无边框表格识别；合并单元格 / 跨页表 / 嵌套表未在自研层解决。
- P1 没有任何真实凭证，接口地址、鉴权、请求响应、配额、错误码、价格全部 `__TBC__`。
- P2 请求构造符合 OpenAI 兼容 `image_url` 规范，但**一次都没发出去过**；`structured_fallback()` 是文本结构化降级。
- 所有阈值是演示默认经验起始值，不是压测结论；真实压测、监控告警 SLO、按部门加权公平队列均在本期之外。
- 分部门权限的完整 13 步数据模型改造（`docs/org-model-change-plan.md`）仍是**方案已定、代码尚未改造**。
