# 05 · 质量门禁、确定性升级与预算熔断（90:10 到底是什么意思）

## 一、原理：为什么不用固定随机分流

### 1.1 两种「比例」根本不是一回事

| 维度 | 固定随机分流（如 80:20） | 基于质量信号的确定性升级 + 预算熔断（90:10） |
| --- | --- | --- |
| 触发依据 | 随机数 / hash | 质量信号（文本密度、OCR 必要性、表格完整度、图片占比、置信度） |
| 「20% / 10%」的含义 | 抽样比例，**必然**有一部分被无差别送进贵链路 | 最贵链路（P2）**最多占 10% 的页**，是**上限 / 熔断线** |
| 正常文档 | 恒定浪费一部分贵链路调用 | **0% 触发**，全部走 P0 |
| 同样输入的结果 | 可能不同（取决于随机） | **相同**（确定性、可重放、可复盘） |
| 成本与质量的关系 | 无关，恒定开销 | 与「疑难页占比」相关 |
| 适用场景 | A/B 实验、灰度放量 | 分级解析、成本与尾延迟可控 |

一句话：**80:20 / 90:10 这类说法，问的是「抽多少比例去做对比实验」；本项目用的 90:10，问的是「最贵链路最多能占多少页」。** 后者不是分流，是刹车。

### 1.2 为什么「正常文档 0% 触发」

绝大多数企业文档的页是「原生电子」的：有文字层、表格结构可抽、图片多为 logo / 页眉这类装饰图。质量门禁对这类页全部通过，直接停在 P0 自研本地解析，不产生任何外部调用。

只有**长尾疑难页**才会升级：整页扫描无文字层、复杂跨页表格、以图承载的公式、需要语义理解的流程图。这类页在真实语料里是少数——这正是「确定性升级」比「随机抽样」省钱的原因：**钱只花在真的难的那几页上**。

### 1.3 `VISION_ESCALATION_RATIO = 0.10` 的理由（定性）

`VISION_ESCALATION_RATIO`（中文说明：视觉/最贵链路升级占比上限）默认 `0.10` `【占位·演示默认值】`。选它的理由只有定性的三条：

| 理由 | 定性说明 |
| --- | --- |
| 成本 | P1 收费 OCR、P2 视觉 LLM 都是按量计费（价格 `__TBC__`）。一批扫描件若无上限地全量升级，会直接打爆预算；硬上限是必要的财务护栏。 |
| 尾延迟 | P2 是跨网络调用，升级页会拖慢整批 `chord` 的合并（合并要等所有分片）。把「最慢的尾巴」锁在 10% 页以内，尾延迟才可控。 |
| 长尾经验判断 | 真实语料里「非 P0 不可」的疑难页通常是少数；`0.10` 既留了余量，又不至于把贵链路放开。 |

> **必须标注**：`0.10` 是**演示默认值，需用真实语料校准**。扫描档案类语料与原生电子文档语料的最优值显然不同；本篇不声称它是最优值，也不给任何实测依据。
> **再次强调**：90:10 **不是**「90% 页走 P0、10% 页走 P2」的配比；它是「P2 最多占 10% 页」的**熔断线**，正常文档应 0% 触发。

### 1.4 质量门禁的信号

| 信号（英文键名） | 中文说明 | 来源 | 偏向 |
| --- | --- | --- | --- |
| `text_density` | 文本密度（页内可抽取字符 / 面积） | P0 抽取 | 低 → 疑似扫描 → 升级 |
| `ocr_required` | OCR 必要性（文字层缺失 + 图像占比高） | P0 探测 | `true` → P1 |
| `table_integrity` | 表格结构完整度（行列 / 框线信号） | P0 结构信号 | 低 → 升级 |
| `image_area_ratio` | 图片面积占页比 | P0 像素/对象统计 | 高 → 关注（但先判是否装饰图） |
| `confidence` | 解析置信度 | 各级产出，复用既有字段 | 低 → 升级 |
| `blank_or_decorative` | 空白 / 装饰图（纯色、二值、小图） | P0 检测 | `true` → **直接丢弃，不升级** |

> 注意 `blank_or_decorative` 的优先级最高：**装饰图不该被升级，该被丢掉**。把「丢」放在「升」之前，能省掉大量无意义调用。

### 1.5 决策表与伪代码

决策表（先看策略，再看信号，最后过预算闸门）：

| 页况 | `ocr_required` | `table_integrity` / `confidence` | 决策 |
| --- | --- | --- | --- |
| 空白 / 装饰图 | — | — | `DROP`（丢弃，不进分块） |
| 原生电子、结构完整 | `false` | 高 | `P0` |
| 扫描页 / 无文字层 | `true` | 高 | `P1`（OCR） |
| 复杂表格 / 低置信 / 需语义 | `true` | 低 | `P2`（再受预算闸门约束） |
| 预算已达上限 | 任意 | 任意 | 标 `escalation_budget_exceeded`，**回退上一级结果** |

伪代码（示意逻辑，**非项目源码**，阈值均为占位）：

```python
# 伪代码：确定性升级决策 + 预算熔断，仅示意，非项目源码
def decide_level(sig, budget, policy):
    # sig：中文说明：本页质量信号集合；budget：预算状态；policy：策略开关
    if policy == "off":                         # 关闭子系统
        return "skip"
    if policy == "local_only":                  # 强制只用本地
        return "P0"
    if policy == "ocr_api":                     # 强制 OCR 档（契约 __TBC__）
        return "P1" if sig.ocr_required else "P0"
    if policy == "multimodal":                  # 强制尝试 P2（当前必降级，仍受预算闸门）
        return budget_gate("P2", budget)

    # auto：确定性升级（默认 / 演示主路径）
    if sig.blank_or_decorative:                 # 装饰图优先丢弃
        return "DROP"
    level = "P0"
    if sig.ocr_required or sig.text_density < T_LOW:        # T_LOW：文本密度阈值，演示默认，待校准
        level = "P1"
    if level == "P1" and (
        sig.table_integrity < T_TABLE                       # T_TABLE：表格完整度阈值，待校准
        or sig.confidence < T_CONF                        # T_CONF：置信度阈值，待校准
        or sig.needs_semantic                             # needs_semantic：是否需语义理解
    ):
        level = "P2"
    return budget_gate(level, budget)           # 最后一道：预算熔断
```

所有 `T_*` 阈值均为**演示默认 / 待校准**，本篇不写死具体数值（唯一已知默认值是 `VISION_ESCALATION_RATIO = 0.10`）。

## 二、本项目怎么落

### 2.1 升级顺序、幂等与去重

- **顺序**：`P0 → P1 → P2` 单向升级；已成功产出的页不回退重跑。升级是「补足上一级的不足」，不是「推翻重来」。`【占位】`
- **幂等键**：复用既有 `chunk.id = uuid5(doc_id, version_no, seq)` 的跨 PG / Milvus 幂等思路 `【已落地】`；升级决策以 `(doc_id, version_no, page_no)` 为去重键，重复入队不重复计费。`【占位】`
- **去重**：同一页、同一级、同一策略版本只调一次外部 API；用「页哈希 + 级别 + 策略版本」做**请求指纹**缓存，避免重试导致重复扣费。所有 API 契约 `__TBC__`。`【占位】`
- **结果承载**：每级产出的 `confidence`（置信度）、`source_level`（来源层级）、`block_type`（块类型）复用既有 `chunk_document` 字段 `【已落地】`，新增链路无需另起一套元数据。

### 2.2 预算闸门与超预算行为

- **计数口径**：按「页」计，`escalated_pages / total_pages`（中文说明：已升级页数 / 总页数）与 `VISION_ESCALATION_RATIO` 比较；达到上限后**不再发出 P2 请求**。`【占位】`
- **绝不静默失败**：命中上限时标 `escalation_budget_exceeded`（中文说明：升级预算超限），**回退上一级结果**——P2 被拦就用 P1 结果；若连 P1 都没有，就用 P0 的结构化降级结果（见 04 篇），并在轨迹里留痕。`【占位】`
- **两层标记的区分**：
  - `escalation_budget_exceeded`：升级**决策层**的拦截（本篇）。
  - `vision_budget_exceeded`：P2 **适配器层**的拦截（04 篇）。
  - 两者可能同时出现，**都要留痕、不能互相吞掉**。
- **与 04 篇的一致性**：P2 当前本就 `【未接通】`（无视觉端点），因此即便预算没拦，强制 `multimodal` 也只会命中 `vision_unavailable` 并降级；预算闸门是在「将来补了端点」之后才真正发挥财务护栏作用。

### 2.3 可观测字段（每页一条轨迹记录）

| 字段（英文键名） | 中文说明 |
| --- | --- |
| `page_no` | 页码 |
| `parser_level` | 本页最终用了哪级（P0 / P1 / P2） |
| `escalated_from` | 从哪一级升级而来 |
| `confidence` | 该级产出的置信度 |
| `elapsed_ms` | 该级耗时（**仅记录字段存在，定性；不写实测数字**） |
| `escalated` | 是否发生升级 |
| `blocked_by_budget` | 是否被预算闸门拦下 |
| `degrade_reason` | 降级 / 留痕原因（如 `vision_unavailable`、`escalation_budget_exceeded`） |
| `policy` | 当时生效的策略开关 |
| `trace_id` | 串联一次解析轨迹的标识 |

> 这些字段服务于**演示轨迹可视化与复盘**，不是压测指标；本篇不据此产出 P95 / 吞吐 / 价格。

### 2.4 三级策略开关与前端交互

`policy`（中文说明：三级策略开关）取值语义：

| 值 | 中文语义 | 典型用途 | 三态 |
| --- | --- | --- | --- |
| `auto` | 质量门禁确定性升级 + 预算熔断 | 默认 / 演示主路径 | `【占位】`（骨架） |
| `local_only` | 全走 P0 自研本地，不调任何外部 | 离线、断网、成本冻结 | `【占位】` |
| `ocr_api` | 强制 P1 收费 OCR（契约 `__TBC__`） | 扫描件批次 | `【占位】` |
| `multimodal` | 强制尝试 P2（**当前必降级**） | 演示「请求构造 + 降级留痕」 | `【未接通】` |
| `off` | 关闭解析子系统 | 灰度 / 回滚 | `【占位】` |

前端交互 `【占位·演示切片】`：

1. 上传页提供分段控件选择 `policy`，并**即时显示预计链路**（例如选 `local_only` 时提示「不会调用任何外部 API」）。
2. 选 `multimodal` 时，前端**明确提示**：「当前无视觉端点，将命中 `vision_unavailable`，仅演示请求构造与降级留痕」——**不误导用户以为能出视觉结果**。
3. 提交后，「解析轨迹可视化」按页着色：P0 / P1 / P2 / 被预算拦下 / 降级留痕，一眼看清每页发生了什么。
4. 命中 `escalation_budget_exceeded` 的页在界面上单列，展示「回退用了哪一级的结果」。

### 2.5 「解析轨迹可视化」为什么是面试加分项

它把「黑盒 RAG」变成**可解释的逐页决策**，能指着一页说出四个词：

| 词 | 轨迹里体现在哪 |
| --- | --- |
| **确定性** | 同样输入同样轨迹，`escalated` / `parser_level` 可重放 |
| **可观测** | 每页都有 `parser_level` / `confidence` / `degrade_reason` |
| **可控** | `blocked_by_budget` 证明预算熔断真的生效 |
| **可降级** | 超预算不静默失败，回退上一级并留痕 |

> 它比「我们接了视觉大模型」更可信：展示的是**工程判断与边界意识**，而不是一个当前根本跑不通的能力。且轨迹字段与既有 `source_level` / `confidence` 天然对齐 `【已落地】`，是「骨架接在真实代码上」而非另搭空中楼阁。

## 三、面试怎么讲

**30 秒版**

> 「我们不用固定随机分流。90:10 里的 10% 不是抽样，是最贵链路最多占 10% 页的熔断线；正常文档 0% 触发。触发靠质量信号的确定性升级——文本密度低、缺文字层、表格不完整、置信度低才逐级往上走，超预算不静默失败，标记后回退上一级结果。」

**2 分钟版**（按顺序）

1. 先纠问题：「80:20 还是 90:10」问的是实验抽样比；本项目是「确定性升级 + 预算熔断」，两者不同维度。
2. 讲 0% 触发：正常电子文档全过门禁，钱只花在长尾疑难页。
3. 讲 `0.10` 的三条定性理由：成本、尾延迟、长尾占比经验判断；**主动补一句「演示默认值，需真实语料校准」**。
4. 讲门禁信号与决策表：装饰图优先丢弃，扫描页升 P1，复杂表格/低置信才升 P2。
5. 讲幂等与去重：`uuid5` 幂等键、请求指纹，避免重试重复扣费。
6. 收在超预算行为：标 `escalation_budget_exceeded`、回退上一级、轨迹留痕，再引出轨迹可视化。

**高频追问与应答**

| 追问 | 应答要点 |
| --- | --- |
| 「到底 80:20 还是 90:10？」 | 都不是随机分流；90:10 是 P2 熔断线，正常文档 0% 触发。 |
| 「阈值怎么定的？」 | 定性三理由 + 明说演示默认值、待语料校准，**不编数字**。 |
| 「超预算会怎样？」 | 不静默失败：标记 + 回退上一级 + 留痕。 |
| 「怎么保证不重复扣费？」 | 幂等键 `(doc_id, version_no, page_no)` + 请求指纹去重。 |
| 「为什么装饰图不升级？」 | 先判 `blank_or_decorative`，丢弃优先于升级，省无意义调用。 |
| 「P2 现在能用吗？」 | 无视觉端点，强制 `multimodal` 只会降级；预算闸门为将来补端点预留。 |

## 四、诚实边界

- `VISION_ESCALATION_RATIO = 0.10` 是**演示默认值，未经真实语料校准**；不声称是最优值，也不给实测依据。
- 成本与延迟**只做定性分析**：不写价格、不写 P95 / 吞吐 / 耗时实测数字，不写具体配额。
- P1 / P2 外部 API 的地址、鉴权、请求/响应、配额、错误码、模型版本、价格一律 `__TBC__`；P2 当前**无视觉端点**，强制 `multimodal` 只会命中降级。
- 所有门禁阈值 `T_LOW` / `T_TABLE` / `T_CONF` 均为占位 / 待校准，未写死具体值。
- 三级子系统整体是**骨架 + 演示切片**（#31 范畴），非上线交付；轨迹字段用于讲解与复盘，**非监控告警 SLO**；真实压测未做。
- `eval/` 冻结对象的 `__TBC__` / `NOT_COMPARABLE` / `real_api` 阻断口径**不变**；本篇三态图例与之相互独立，不改动、不绕过。
- 预算闸门在「当前无端点」时主要是设计护栏；其财务价值在将来补端点后才真正体现，本篇不提前邀功。

> 小结：把「比例」纠正成「熔断线」，把「随机」纠正成「确定性」，把「静默失败」纠正成「标记 + 回退 + 留痕」——这三个纠正，就是分级解析设计的全部要点。
